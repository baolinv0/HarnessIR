# HarnessIR 参考驱动摄影师式修图方案

版本：设计稿 v1.0  
日期：2026 年 10 月 28 日  
用途：供工程师实现、完成首轮路线验证，并用一份 Markdown 报告回传结果。  
范围：方案设计，不代表已完成 PhotoCraft 集成、图像实验或效果验收。

## 1 决策摘要

本方案的主线是：让大模型承担摄影师的观察、解释和决策，让程序承担可靠测量和参数求解，让 PhotoCraft 承担可重放的确定性修图，最后分别检查“是否接近参考风格”和“是否保持原图内容与自然性”。

目标不是让大模型说出更多形容词，也不是把参考图的直方图机械复制给输入图，而是得到一张实际可用的图像 C：内容、构图与几何来自 A，颜色、亮度层次和局部明暗关系合理地向 B 靠近，整体看起来像同一种相机成像风格。

当前优先验证这条直接路线：

A 与 B → 建立可比区域 → 程序测量差异 → 大模型解释差异与设定目标 → 大模型选择调色操作 → 数值方法求解参数 → PhotoCraft 渲染 → 程序与视觉复核 → 必要时有限修订。

不把生成图作为必经中间结果。现有直接参考增强 Qwen 流程保留为主要对照；“先生成理想图，再投影成保真变换”只作为后续备选，不与主线一起全面铺开。

首轮只回答一个决定方向的问题：在同场景、同内容、拍摄间隔 5 秒内的 A/B 上，这条摄影师式工具调用路线，能否比当前较强的直接生成编辑路线，更稳定地同时达到参考风格与内容保持。

## 2 已知事实与尚未证明的假设

### 2.1 用户已明确的条件

- A 与 B 是同场景、同内容，拍摄前后差异在 5 秒内。
- A/B 不应被当作天然像素对齐的图像。
- 用户尚未验证：仅用 PS 式颜色、影调和局部蒙版操作，是否能够达到认可的参考风格。
- 希望延续现有 HarnessIR/reference-retouch，而不是另建一个无关系统。
- PS 部分拟采用开源 PhotoCraft。
- 用户需要可交给工程师的完整方案，结果宜以单文件文本报告回传。

已有项目背景是 S26 线性输入经过既有基线得到 prediction，iPhone RGB 为参考；具体实验必须按实际文件与处理链核实。JPEG 对 JPEG 的快速样例不能冒充这组正式实验。

### 2.2 本方案的核心假设

H1：主要目标差异可由受约束的颜色和影调操作表达，不依赖重绘内容。

H2：同场景短时间间隔使相应区域的统计信息具有较高参考价值，但不是所有统计差异都应该迁移。

H3：大模型可以比固定规则更好地解释场景、确定优先级并选择操作，但精确参数应由实际渲染反馈校正，而不是相信一次语言预测。

H4：可重放的调色工具能够降低结构重绘风险，但仍可能造成截断、偏色、光晕、层次丢失和噪声放大，必须独立验收。

以上均为待验证假设。不能把“摄影师会这样做”直接等同于“大模型已经具有同等能力”，也不能把“非生成”直接等同于“保真”。

### 2.3 PhotoCraft 已核验能力与剩余边界

已对官方仓库 https://github.com/storytold/photocraft 做只读源码核验，固定版本 v0.16.0，提交 b1794c6e0608ccfc887213dcf58398977c5cb75e。项目仍为 early alpha。本次没有安装、运行或做真实图像 round-trip，以下“支持”仅表示相应源码路径存在，不代表运行验收通过。

- 项目清单声明 MIT OR Apache-2.0，Rust 1.95，并使用固定版本依赖。这不替代全部第三方依赖及分发条件的审查。
- CLI document 路径通过 Headless::trusted_local 打开文档、执行结构化命令并保存；Headless::command_run 可同步执行。可以选择 Rust 内部调用或隔离 CLI worker，不必依赖 UI 点击。
- 调整参数解析包含 exposure、curves、levels、vibrance、hueSaturation、colorBalance、selectiveColor、colorLookup。曲线与色阶的通道参数采用 0–255 语义，不能直接填入 0–1 或未经转换的 Lab 值。
- 存在图层蒙版 density、feather 属性；创建 adjustment 时可从当前 selection 生成同文档位深的蒙版，也存在 vector mask 路径。任意外部分割掩膜的一步 CLI 导入接口尚未确认，不能编造现成 mask.import 命令。
- CPU 合成存在按文档 bounds 渲染和分带渲染路径。正式实验固定 CPU 后端、build 与色彩设置，不与 GPU 路径混用。
- 色彩命令区分 assignProfile 与 convertToProfile；前者改变解释，后者执行颜色转换，不能互换。I/O 源码含 U8、U16、F32 与 ICC 处理及降精度警告，但具体格式、位深和 profile 的导出往返仍需运行验证。
- automation::files::render_png 即使 max_side=0 也经过 thumbnail 与 Image::from_u8。它可用于观察预览，但不能用来证明浮点或 16 bit 精密处理与最终交付。

因此，PhotoCraft 已有足够具体的可集成基础，不必从零造 PS；同时，外部掩膜绑定、工作域一致性、原生高精度导出与重放仍属于 M0 的必要验收。

后文列出的适配器方法和统一操作规范是 HarnessIR 的拟建接口，不是声称 PhotoCraft 已存在同名 API。与 Photoshop 的数值一致性不作承诺，也不作为首轮目标。

## 3 成功目标与明确不做的事情

### 3.1 目标

1. 参考利用充分：每个重要的可迁移差异都进入目标，目标进入操作，输出按同一目标核查。
2. 内容保持：不改变人物身份、文字、物体数量、轮廓、构图与视角，不从 B 复制纹理到 A。
3. 风格接近：改善整体色调、肤色或关键色、亮度分配、主体与背景关系以及高光和阴影层次。
4. 局部与整体协调：一个区域变得更接近 B 时，不以破坏其他区域为代价。
5. 可解释和可重放：能够指出改了哪里、为什么改、采用什么操作及参数，能够从原始 A 重新渲染同一结果。
6. 可判定失败原因：区别目标理解错误、区域对应错误、求解不足和工具表达能力不足。

### 3.2 首轮不做

- 不训练或微调新模型，不开展四编辑器、多 VLM 的大矩阵。
- 不追求完全复现某手机的隐藏 ISP，也不声称从一对图像识别出完整相机风格。
- 不自动改变人脸形状、物体结构和纹理，不引入生成式填充。
- 不以完整复刻 Photoshop UI 为前提，不把鼠标点击自动化作为主实现路线。
- 不要求所有区域的直方图与 B 完全相同，不把 PSNR 当作非对齐风格迁移的主排名指标。
- 不为每个细小参数单独开展消融。先证明完整路线有价值，再追查决定性瓶颈。

## 4 为什么选择这条路线

### 路线 A 继续直接生成编辑

输入 A/B，经诊断和提示构造直接调用图像编辑模型。优点是表达能力强，能够统一处理复杂视觉变化；不足是区域控制、参数可追踪性、细节保持和原生分辨率交付容易受模型限制。它保留为强对照，而不是被默认否定。

### 路线 B 摄影师式工具调用

大模型解释和规划，统计测量与数值求解落实幅度，确定性工具修改 A。优点是动作可追踪、可重放、方便局部保护；风险是工具能力不足或目标表示遗漏了真正的风格。当前用户选择的方向对应此路线，本方案将其作为主线。

### 路线 C 生成提案后投影到受约束变换

先生成视觉目标，再求一个尽量保真的颜色/影调变换。它可以缓解语言目标不完整的问题，但同时增加中间目标错误及投影损失，不能默认比直接 A/B 求解更合理。仅当路线 B 的目标表达被证明确实不足时再进入，不作为首轮额外主臂。

## 5 职责划分

| 环节 | 主要责任方 | 输出 | 不允许承担的责任 |
|---|---|---|---|
| 文件、色彩和几何审计 | 程序 | 文件元数据、色彩处理记录、原生尺寸 | 以文件名推测真实处理链 |
| 语义识别与参考可比性解释 | 大模型结合视觉工具 | 区域标签、对应关系、排除项和置信说明 | 编造像素统计或精确曝光值 |
| 区域掩膜与对应支持 | 分割/匹配工具，必要时人工修正 | A/B 各自的掩膜、有效支持、可靠性 | 直接把 B 掩膜缩放后视为 A 掩膜 |
| 差异测量 | 确定性程序 | 亮度分位、颜色、截断、区域关系 | 将每个测量差自动解释成应该修复的错误 |
| 目标解释与优先级 | 大模型 | 有证据的目标、保护要求、不确定项 | 将不可比区域设为高置信硬目标 |
| 操作与区域选择 | 大模型 | 有限操作序列、掩膜和参数边界 | 输出任意代码或无界参数 |
| 精确参数求解 | 数值优化器 | 经真实渲染校验的参数候选 | 无视整体观感只追一个统计量 |
| 图像执行 | PhotoCraft 适配器 | C、渲染记录、异常 | 未声明的自动增强和隐藏重采样 |
| 数值验收 | 程序 | 达成度、保护检查、数值风险 | 代替对参考风格和自然性的最终判断 |
| 整体视觉验收 | 独立视觉判断，人审校准 | 风格相似、协调性、残余问题 | 仅凭规划文本宣布成功 |

“局部交给传统方法、整体交给大模型”不是严格边界。全局亮度也适合统计，局部肤色是否自然也需要语义和视觉判断。真正的分工是测量、解释、控制与验收。

## 6 数据契约和色彩管理

### 6.1 每例必须记录

- case_id、A/B 文件路径或稳定标识、文件哈希。
- 拍摄设备、拍摄时间与间隔，若 EXIF 缺失则明确为人工提供或未知。
- A 的来源：线性数据、基线 prediction、JPEG 或其他，不得混用名称。
- A/B 的原生宽高、方向、位深、通道、ICC 或已知传递函数。
- RAW/线性到显示图的处理链和版本；若无法恢复，记录已知边界。
- 可疑差异：运动、表情、遮挡、闪光、自动曝光、自动白平衡、视角和焦段变化。

同场景且间隔短只提高可比性，不自动通过审计。表情变化、人脸转向和局部反光都可以在 5 秒内发生。

### 6.2 建立统一的观察域

A/B 用同一已声明的色彩管理路径转换到工作域。建议首轮采用明确标识的 SDR 显示工作域，并保留原文件；不能把显示 RGB 代码值直接叫作物理亮度。

- 测量明暗趋势时，可同时保留感知亮度指标和在线性化工作域计算的相对亮度 Y。报告必须标明使用哪一种。
- 在已正确转换且白点明确的条件下，使用 Lab 类颜色表示计算颜色分布与色差趋势。不能直接对未知编码 RGB 套用 Lab 公式。
- JPEG 上的“加曝光”是显示图的后期变换，不等同于传感器曝光增加，也不能从它恢复已截断的信息。
- 参数求解工作域与 PhotoCraft 的实际运算域必须一致，或者在适配器中明确转换；不能用线性域模型预测参数，却调用未经校准的 sRGB 滑杆。
- 若 ICC 缺失，只能使用记录在 manifest 中的工作假设；不隐式自动猜测后继续声称高精度颜色结论。

### 6.3 预览和原生分辨率

统计和候选搜索可用固定的等比例预览，以降低成本；最终必须从原始 A 在原生尺寸重新渲染。掩膜坐标、羽化半径和局部算子的空间尺度按明确规则映射，不能将预览输出放大当成原生结果。

如果 PhotoCraft 已核验路径只支持有限精度或特定尺寸，必须在能力清单中披露。不能一面在方案中要求浮点流水线，一面无记录地落入 8 bit 多次往返。

## 7 区域建立与可比性

### 7.1 只选择影响结果的少量区域

首轮建议每例 3 至 6 个关键区域，而不是对全图建立几十个对象。典型人像场景可包括人脸皮肤、头发或衣物、背景、明亮背景或窗户、深阴影；应按实际图像决定，不强制每例齐全。

同一个语义类别不一定是同一个可比对象。例如两处皮肤可以处于不同光照，背景中多个墙面可能有不同朝向。必要时细分，而不是盲目聚合。

### 7.2 A/B 分别获得掩膜

复用 HarnessIR 已可用的分割或检测工具，但先核验当前分支是否实际调用。大模型提出区域名称和对应候选，程序/视觉工具生成 A 与 B 的各自掩膜。大模型不能用未经验证的文字框选替代精确像素掩膜。

每个对应对保存：region_A_id、region_B_id、语义、实例关系、可比等级、有效像素数、排除原因和置信来源。

可比等级使用离散决策：

- comparable：同一对象且有效支持相近，可形成定量目标。
- partially_comparable：支持或光照存在差异，只形成方向、区间或弱约束。
- not_comparable：不建立直接数量目标，仅作为场景解释或明确排除。

置信度是证据等级，不是未经校准的概率。不要把 VLM 自报 0.95 当成真实 95% 正确率。

### 7.3 统计使用有效内部支持

对掩膜内部做适度边缘剔除，去掉遮挡、边界混色、严重过曝和错误分割。所有排除规则和剩余覆盖率必须记录。剔除过多时降级为不可比，不能仅留下最容易匹配的一小块后声称区域匹配成功。

A/B 视角变化明显时，优先比较同材质、同受光部位的有效支持；必要时使用配准或特征匹配建立辅助对应，但不能让低置信的形变结果污染颜色目标。掩膜用于编辑的区域可以比用于测量的有效支持更广，两者必须分开保存。测量与验收 ROI、有效支持和排除规则随目标合同冻结；外层可修订编辑 mask，但不得移动测量 ROI 来追分。确需修正对应或测量支持时，建立新合同版本，保留旧结果；正式集上这属于协议偏离，不能与原冻结结果混为一次主实验成绩。

### 7.4 自动化失败的处理

自动掩膜失败时返回明确状态。开发阶段允许保存一版人工修正掩膜进行诊断，但人工辅助结果与全自动结果分开报告。正式集主结果不得悄悄换成人工掩膜。

若人工掩膜显著改变结论，说明问题可能在区域识别/对应，而不是色彩工具本身；这是一项按失败触发的诊断，不是默认增加一整套实验臂。

## 8 量化测量应该回答什么

### 8.1 亮度与层次

每个可信区域计算固定分位点，例如 P10、P25、P50、P75、P90；同时记录暗端和亮端截断比例、有效面积。用分位而非仅均值，可以区分“整个区域偏暗”和“只有阴影压得更深”。

测量示例是“人脸中间调低于参考，亮端相近”，其控制含义可能是提升中间调而保护高光。不能从一个均值差直接推出整张图统一加曝光。

### 8.2 颜色和饱和度

在可比支持上计算稳健的亮度与色度统计，以及按亮度分层的颜色分布。暗部受噪声影响、亮部受截断影响时，降低这些像素对色彩目标的权重。

肤色不宜只设一个平均 Lab 点。至少同时观察主体肤色的离散程度、阴影和亮部的变化方向，以及与其他区域的关系。肤色更靠近 B 但变得均匀蜡感，仍应判失败。

直方图或分布距离可以作为趋势诊断，前提是比较相同内容和支持。它不是空间结构描述，也不是最终“风格分数”。

### 8.3 区域关系

摄影风格的重要信息来自关系：人脸与背景的亮度分离、肤色与环境色的对比、高光和中间调的跨度、主体与背景的色温关系。

因此目标必须包含区域间关系，而不是只包含独立 ROI。比如“脸部向参考提亮，但不超过参考中脸与背景的相对分离”，可以防止局部完成、整体失衡。

### 8.4 不适合直接迁移的量

- 有明显构图比例变化时的整图直方图。
- 受反光或表情变化影响的极端分位。
- 无可靠配准的逐像素颜色差、PSNR 和逐像素 ΔE。
- 物体位置变化导致的局部亮度差。
- 来自 B 的噪声、压缩、锐化或纹理特征，除非另立任务并有明确授权。

不论统计数值多精确，只要其比较对象不成立，就不能成为精确控制目标。

## 9 从差异生成不可变参考目标

### 9.1 大模型的任务

输入 A/B 预览、区域视图、经过程序计算的证据及其置信限制。大模型应输出：哪些差异应该迁移、为什么、优先级、目标类型、保护项，以及哪些差异不应迁移。

每个目标必须引用实际 observation_id 和 region_id。没有测量支持的视觉判断可以作为 perceptual_goal，但不能伪装成已测定的数值目标。

### 9.2 目标类型

- 数量区间：可信对应区域的中间调或颜色目标，允许容差。
- 方向目标：证据较弱但可靠地判断为偏暖、偏暗等，不给虚假精确值。
- 关系目标：主体与背景的明暗或颜色关系。
- 感知目标：整体氛围、自然性、局部协调等，需视觉检查。
- 保护目标：身份、文字、几何、有效细节、未授权区域等。

参考目标不是要求 C 的所有统计量等于 B。对部分可比区域，宜保留 B 的方向或相对关系，并为源图内容和受光差异留出空间。

### 9.3 目标合同的最小字段

| 字段 | 含义 |
|---|---|
| contract_id / version / hash | 不可变目标的身份 |
| source_hash / reference_hash | A/B 绑定 |
| observations | 实际测量、单位、工作域、置信依据 |
| region_pairs | 双侧区域与可比性 |
| targets | id、类型、优先级、证据引用、目标/区间/方向 |
| protected_properties | 不得牺牲的内容与画质 |
| exclusions | 明确不迁移的差异 |
| acceptance_rules | 每个目标的验收方式、必选或可选 |
| uncertainties | 已知不确定性与降级策略 |

合同在正式求解前冻结。反馈只能改变执行计划、参数和可允许的掩膜修订，不能因为当前结果难以达标，就悄悄放宽目标或把 mandatory 改成 optional。确实发现参考解释错误时，必须建立新合同版本，并单独记录修订原因与前后差异。

### 9.4 贯穿式目标示例

以下是说明接口的假设案例，不是已观察到的实验结果：程序测得 A 的可信皮肤区域中间调低于 B，而亮端接近 B；背景的亮度关系基本合理。大模型据此提出“局部提升脸部中间调，保护亮端，并维持脸与背景的合理分离”。不能直接把整图曝光提高作为唯一方案。

目标对象的示意如下，数值由程序填入，不由 VLM 填造：

```json
{
  "target_id": "face_midtone",
  "kind": "interval",
  "region_pair_id": "face_pair",
  "metric": "Y_linear.P50",
  "reference_value_ref": "obs_B_face_Y_P50",
  "tolerance_ref": "dev_tolerance_face_Y_P50_v1",
  "priority": "mandatory",
  "comparability": "comparable",
  "evidence_ids": ["obs_A_face_Y_P50", "obs_B_face_Y_P50"],
  "protect_target_ids": ["face_highlight", "face_background_relation"]
}
```

其中 target interval 由 reference_value 和已冻结 tolerance 解析生成；若该 ROI 只能部分比较，则改成 direction 或更宽的 interval，不能仍写高置信 exact target。face_highlight 约束高分位与新增截断；face_background_relation 约束两区中位亮度关系，防止“脸到位但背景失衡”。

对应计划只表达结构：选择局部曲线，作用 mask_A_face，固定端点并限制单调性，优化中间控制点；每次渲染后同时检查上述三个目标。曲线控制点在 HarnessIR 中统一规范，适配器再映射成 PhotoCraft 0–255 坐标。实际 B 的测量、容差与参数均进入报告，不把示例写成默认所有照片都要提亮人脸。

目标容差由开发集上的统计稳定性、掩膜支持变化及用户可接受差异共同制定并冻结。初值可以用受控 mask 轻微扰动下的测量变化界定测量底噪，再由人审确认其视觉合理性；不能用 VLM 自报精度确定容差，也不能在正式失败后扩大容差。

## 10 大模型生成可执行修图计划

### 10.1 计划应短而可执行

每次外层规划只选择少量操作，并给出对应目标。例如：先修正全局色偏，再调整总体曲线，再局部提升人脸中间调，最后处理背景亮部；每一步都解释作用区域和可能伤害的目标。

一个推荐的首轮上限是全局操作不超过 3 个，局部操作不超过 3 个。这个上限是控制复杂度的工程初值，不是摄影规则。确有证据需要增加时，在开发集修订后冻结。

### 10.2 最小操作集合

以下是需要映射到 PhotoCraft 实际能力的逻辑操作，不代表其现有命令名：

1. 全局或局部明暗调整：单调曲线，或者已校准的曝光/明暗操作。
2. 中性平衡或全局颜色校正：可控通道变换，限定幅度。
3. 色度/饱和度调整：避免无界增强，保持必要的亮度关系。
4. 局部蒙版合成：对选定变换施加有边缘过渡的空间权重。
5. 必要时亮度范围选择：在同一区域中保护高光或限制阴影操作。

不在首轮堆叠十几种相互重叠的滑杆。若 PhotoCraft 不支持某一逻辑操作，适配器返回 unsupported；不得用名称相似但作用不等价的功能偷偷替代。

### 10.3 每步操作的约束

保存 tool_type、target_ids、mask_id、参数定义、搜索范围、默认值、顺序、混合方式、保护要求和预期效果。

大模型可以提出参数初值，但不把初值视为准确答案。工程层验证取值范围和工具能力，只接受白名单操作及结构化字段，不执行模型生成的任意脚本。

操作顺序会影响结果，因此序列是计划的一部分。不得以“相同参数集合”为由忽略顺序变化。

## 11 PhotoCraft 适配层

### 11.1 适配目标

采用已核验的 Headless 结构化命令路径，而不是 UI 点击。首版可用受限的独立 worker 调用 CLI；需要精确获取浮点像素、绑定外部掩膜或避免重复序列化时，再通过 Rust API 建立薄封装。两种接入方式共享同一 HarnessIR 能力契约，不另立两套研究路线。

适配器既是调用封装，也是能力与语义边界。HarnessIR 不应直接依赖随版本变化的 UI 控件名称。

### 11.2 拟建接口

建议提供以下内部接口，名称可在实现中调整：

- inspect_capabilities：返回当前版本、可用操作、参数域、掩膜、精度、色彩、导出及确定性说明。
- validate_plan：检查计划是否能被当前后端精确执行。
- render_from_source：从不可变原始 A、计划、参数、掩膜生成 C。
- export_native：导出原生尺寸的指定格式并验证实际结果。
- replay：按保存的 manifest 重新执行并报告差异。

这些均为拟建的 HarnessIR 接口。底层 command_run 已有同步执行代码，具体命令名与 payload 由白名单注册表映射，不由 VLM 自由生成。trusted_local 只能在经过命令、类型、路径和预算校验的本地 worker 内使用，不把它作为任意模型调用入口。

### 11.3 能力清单最小结构

每项能力至少记录：supported、implementation_path、verified_commit、input_domain、output_domain、parameter_semantics、mask_support、bit_depth、native_resolution、determinism_status、known_limits。

支持状态分为 code_verified、runtime_verified、unsupported、unknown。README 声明不能直接标成 runtime_verified。尚未运行的接口必须保持 unknown 或 code_verified。

### 11.4 真实参数域与适配规则

源码的 exposure 允许约 [-20,20] EV，offset [-0.5,0.5]，gamma [0.01,9.99]；vibrance/saturation [-100,100]，hue [-180,180]，colorBalance 数组 [-100,100]。这些是实现接受范围，不是本任务的安全搜索范围。工程师必须在开发集上设定明显更窄的工作区间，并在 manifest 中冻结。

部分源码会 clamp 而不是报错。适配器应预先拒绝未知键、错误类型与越界值，保存请求值及实际接受值，避免优化器以为执行了参数 x，后端实际使用了 x 的截断值。名称为 EV 的后期操作也不能让显示 RGB 统计量自动获得物理曝光含义，仍须在正确工作域校准。

已核验的是当前 selection → LayerMask 路径。外部分割 mask 的读入与绑定列为适配器开发及 M0 验收任务，可评估 Document/Surface 薄封装，尚不声称存在现成导入接口；新增封装明确标记 HarnessIR adapter extension。检查尺寸、坐标、位深与灰度含义，不能未经转换直接把浮点概率图当图层 mask。使用 density/feather 时分别记录原始 mask、实际变换后 mask 与像素尺度。

assignProfile 只用于明确指定原像素应如何解释；需要统一工作空间时使用 convertToProfile。未知源 profile 不得用“assign 成目标 profile”伪装成颜色转换。导出通过 compose 浮点缓冲或 io::export/Headless::save 的明确格式路径完成，记录实际位深、ICC、降精度 warning；有 warning 时不得静默当作高精度成功。

### 11.5 最小工程验证

这些是防止错误结论的接入验收，不是研究消融：

- identity：空计划输出不得发生隐式缩放、裁剪、方向变化或未声明的颜色处理。
- single_operation：已知测试图上验证操作方向、参数范围、裁剪和边界行为。
- mask_locality：全零、全一和局部掩膜的语义符合定义，区域外不会出现未声明变化。
- replay：同输入、版本、计划和后端重复渲染的差异已量化。
- native_export：实际导出宽高、色彩标记、位深和内容范围满足要求。

正式首轮固定 CPU、build、工作域与导出 profile，不宣称跨平台逐位一致。在固定环境中保存重放哈希；若不能逐位相同，报告最大像素误差及容差依据。分带渲染另检查边界接缝和与整图渲染的差异，不能仅验证宽高。导出异常必须中止该例的成功状态。

### 11.6 工具缺口的处理

如果核心操作缺失，优先缩小首轮工具集合并检查是否仍能覆盖目标；如确需补一个小型确定性算子，应将其单独命名为 HarnessIR 扩展，明确不是 PhotoCraft 原生能力。大规模重写图像引擎不属于本轮方案。

## 12 参数求解和内外层循环

### 12.1 外层解决结构选择

大模型决定用什么工具、作用哪个区域、先后顺序以及哪些目标最重要。外层每次只修改有明确证据的计划问题，不反复自由改写整套目标。

### 12.2 内层解决幅度

在一次内层求解中，固定操作序列、掩膜和目标合同，只优化有界数值参数。这样才能区分“选择了错误工具”和“正确工具的参数没调好”。

首轮默认采用确定性的有界坐标搜索，不比较一组优化器。仅在实际性能阻碍完整闭环时另行替换，替换后重新冻结开发协议。

参数数目应保持低维，推荐首轮每例同时活跃的自由度不超过约 12 个。若一个目标需要几十个互相抵消的参数，先检查目标表示、区域划分和操作集合，而不是立即扩大搜索空间。

### 12.3 目标函数由多类误差组成

参数搜索可组合以下项，但不能把所有质量压成一个未经验证的总分：

- 参考差异项：可信区域的分位、颜色与区域关系误差。
- 保护项：新截断、亮暗顺序异常、未授权区域变化、异常色域值。
- 正则项：变换幅度、曲线平滑性、蒙版边界过渡、过多操作惩罚。

目标按合同优先级和证据可靠性加权；单位必须归一化，防止某个数值量纲支配全部优化。低置信或不可比区域不能因面积大而压倒主体。

可行性与保真约束优先于参考相似度：违反内容/导出硬约束的候选不能因为统计更接近 B 而被选中。

具体起步定义如下。对第 j 个数量目标，测量为 m_j，冻结区间为 [l_j,u_j]，冻结容差尺度为 t_j>0，残差取 r_j = max(l_j-m_j, 0, m_j-u_j) / t_j。方向目标用相应单侧 hinge；区域关系目标先计算两个区域的关系量，再用同样的区间残差。不要将未归一化的亮度、色差直接相加。

先对每个区域/关系组内部的目标求平均，再按合同优先级与可靠性聚合，不能按像素面积加权。初版可靠性权重可固定为 comparable=1、partially_comparable=0.25、not_comparable=0；这是透明的工程权重，不是概率估计。优先级权重及正则系数也在开发阶段固定，报告原值。必须项是否通过仍逐项判断，不能用加权总分掩盖某个必选项失败。

进入软目标评分前执行硬拒绝：非法参数、非单调受约束曲线、无效掩膜、异常尺寸/方向、不可接受的新增截断及其他合同硬约束违规候选直接淘汰。可编程检查不了的身份、自然性等硬失败，在原生视觉验收后淘汰，不能假装已在数值内环完全解决。

默认求解过程：

1. 固定合同、操作顺序、mask、参数安全上下界与扫描顺序。每个参数提供能代表 identity 的初值；整体从 identity 开始，并保留原始 A。若加入新操作，先验证其零效应值确实是 identity。
2. 将各参数缩放到可比的规范区间，初始步长设为其安全区间宽度的 1/4；这是起步配置，开发后冻结。每个完整扫描按稳定顺序评估当前参数的 +step 与 -step 两个合法候选。
3. 对合法候选从 A 重新渲染，先硬约束再软误差。仅接受超过冻结数值精度阈值的改善；并列时优先变换幅度更小者，再按固定顺序选择，避免随机漂移。
4. 完整一遍没有改善，则所有活跃步长减半。某参数低于其冻结最小可辨步长后不再扫描；全部达到该尺度，或单轮/总预算耗尽即停止。
5. 缓存键包含输入、合同、操作序列、mask、参数、工作域和后端版本的哈希。完全相同的候选复用数值结果，不重复渲染；不同计划或 mask 不能错误命中缓存。
6. 返回本轮最佳有效候选及目标残差；外层据此决定保留、修改结构或终止。换操作序列或修订 mask 后重建内层问题，从原始 A 重放，不在旧输出上继续叠加。

VLM 给出的参数初值可以记录为建议，但首轮主方案不依赖其精确性。先采用统一 identity 起点以便复现；如果以后发现可验证的参数热启动能显著节省成本，再作为一次明确的工程修改。

### 12.4 不进行盲目直方图匹配

直方图匹配可以作为某个可信区域的候选变换或诊断，但必须受单调性、幅度、空间过渡和全局关系约束。相同直方图不意味着同一张自然照片，反过来，略有不同的直方图也不意味着风格失败。

### 12.5 所有候选从原始 A 重渲染

每次内层评估和外层修订都重新执行完整操作栈。禁止对上轮输出反复编码、叠加编辑，避免不可追溯的累计截断和量化。

局部参数更新后重新计算全部关键区域及区域关系。不能只验局部达标就停止，也不能让后续全局调整把已达标的局部目标破坏而不知情。

### 12.6 候选保留和停止

始终保留原始 A、当前最佳有效候选及必要的失败候选记录。没有安全改善时返回 A 或最佳有效候选，并标记未完成，不能为了有输出而强制提交最后一轮。

停止条件包括：必选目标已满足且无硬失败；连续一轮修订没有实质改善；预算耗尽；参考不可用；后端不可用；已确认工具表达能力不足。不同停止原因必须区分。

## 13 首轮预算与默认配置

以下为工程建议初值，工程师可在开发样本上根据实际成本调整一次，然后冻结，不应被写成已验证最优配置。

| 项目 | 建议初值 | 目的 |
|---|---:|---|
| 关键区域 | 每例 3 至 6 个 | 聚焦决定观感的关系 |
| 外层计划修订 | 最多 3 轮，含初始计划 | 限制自由反复判断 |
| 单次内层渲染 | 最多 40 次预览评估 | 为低维搜索提供反馈 |
| 总预览渲染 | 每例最多 120 次 | 预算可核查 |
| 活跃参数 | 约 12 个以内 | 防止欠约束与互相抵消 |
| 原生候选导出 | 最多 3 个 | 检查预览未发现的问题 |
| VLM 调用 | 每例建议不超过 8 次 | 诊断、计划、修订、独立检查分开记账 |

分割、统计、优化、渲染与大模型时间分别计量；缓存区域与证据。任何预算超支必须记录原因。正式实验不能对困难样本临时无限加预算，对简单样本却提前停止后只比较最佳结果。

低成本预览与全分辨率渲染的结果不一致时，最终以原生结果验收。预览达标只标 preview_pass，原生输出重新测量、检查内容和导出属性后才可能 accepted。若原生失败，在原生导出预算内尝试下一已保存候选；全部不通过则返回 A 或明确未完成的安全候选，绝不使用预览通过代替原生验收。必要的最终检查不应被预算截断后仍标成功。

## 14 独立验收

### 14.1 四个维度分开报告

1. 参考匹配：C 比 A 是否更接近 B 的颜色、影调和关系；是否还有必选目标缺失。
2. 内容保持：人物身份、文字、对象、轮廓、几何和构图是否保持。
3. 自然协调：肤色、局部过渡、明暗关系和整图是否合理；是否出现光晕、偏色、平板或“拼贴式”观感。
4. 交付有效：原生尺寸、方向、色彩与输出格式是否满足要求，是否可重放。

“overall improved”不能替代上述四项。参考更像但人脸内容改变，或者内容保持但风格没有改善，都不是任务完成。

### 14.2 程序验收

用冻结的合同检查每个 target_id，不允许遗漏必选项。重新测量 C，不沿用优化器缓存中的预测值。记录每项达成、部分达成、未达成或不可判定，以及量化残差。

检验不只复用优化目标，还包括未用于优化的保护信号和原生尺度检查。否则容易出现“优化哪个指标就用哪个指标宣布成功”的循环证明。

区域外不变的要求应与操作类型一致：全局调色必然影响全图，不能一面允许全局校正，一面要求所有非 ROI 像素完全不变；应对未授权空间操作和内容变化做明确区分。

### 14.3 视觉验收

独立视觉评审查看 A/B/C 的规范化视图和必要局部裁剪，不看编辑模型身份、上游判断理由或“本方案应当成功”的叙述。可看冻结的目标，但不得因操作计划声称达成而认定达成。

视觉评审输出每个必选目标、整体协调、内容保持及具体残余问题。它与规划模型可以暂时同型号，但提示、上下文、输出职责隔离；这不是统计独立性的保证，仍需人审校准。

已有 Stage Lab 的模型评审与人审一致性不足，因此本轮不把 VLM 单独决定的通过率作为主要结论。

### 14.4 人工主验收

正式对比采用匿名、随机左右排列。第一步只依据 A、B、候选及原始完整用户目标，判断参考风格、内容保持、整体协调与任务是否完成；第二步再看冻结合同进行逐目标核查。不能让 T 自己生成的合同定义全部成功标准，否则漏掉重要参考差异后，两臂都可能按缩水目标通过。评审应明确指出合同遗漏的目标，而不是为了保持合同一致而忽略它。不要只问哪张更好看。

条件允许时由两名评审独立判断；若仅用户一人评审，明确单评审限制。出现分歧时保留原始标签，必要时讨论形成解释，不能把讨论后的共识冒充独立一致率。

同一案例的区域、候选和 seed 不是独立样本。正式统计以图像对为单位，不把多个 judge 输出当成大量独立证据。

### 14.5 成功状态

- accepted：必选目标完成，内容、自然性与交付要求通过。
- improved_incomplete：有改善，但仍有必选目标缺失。
- already_satisfied：A 已满足参考目标，正确返回 A。
- no_safe_improvement：没有找到安全改善，返回 A 或保留候选并说明。
- reference_insufficient：参考或对应不足，不能支持目标。
- execution_failed：工具、导出或运行失败。

程序 completed 仅表示运行结束，不能自动映射 accepted。

## 15 HarnessIR 集成方式

### 15.1 复用什么

复用 reference-retouch 已有的 A/B 输入、诊断证据结构、目标合同、目标冻结、验证结果和反馈状态机制。替换或增加 Executor 路由，而不是将统计、工具调用和渲染又压回一段编辑 prompt。

新路由可暂称 reference_tool_retouch_v1，最终名称由工程师与现有命名约定统一。原有 reference_retouch_v1 的生成执行路径保持可用，保证对照可复现。

### 15.2 需要新增的逻辑模块

- ColorContext：工作域、编码、预览与原生映射。
- RegionPairBuilder：A/B 分别建区、对应和可比性。
- EvidenceExtractor：确定性统计、单位、有效支持与质量标记。
- RetouchPlanner：目标到白名单操作计划。
- ParameterSolver：冻结结构后的有界参数求解。
- PhotoCraftAdapter：能力清单、验证、渲染、导出、重放。
- ToolRetouchVerifier：逐目标、保护、自然性和交付验收。

这些是职责划分，不要求一开始就做成七套复杂服务。首版可在现有工程内以简单模块实现。

### 15.3 必须核对的现有状态

此前公开 reference 分支核验到提交 9073086bd86cff3062eab65bcbc32da6e4fd2114。另有本地修补提交 34cd7eb 的报告，但本方案未验证其当前内容是否已经合入或推送。

工程启动先固定实际工作树与提交，并做差异核对；不要直接重复修补已经在本地解决的问题，也不要以公开分支的旧缺口推断本地仍然缺失。

此前公开流程值得核查的连接点包括：证据补充后的状态更新、目标级不确定性是否完整进入执行、target_results 中的修正建议是否触发反馈、逐目标验收与最终状态是否一致。这里列为核对项，不宣称当前本地仍有同样缺陷。

### 15.4 状态流转

输入审计通过后建立区域与证据；证据足够才冻结合同；能力验证通过才进入求解；每个候选执行后进入验收；失败按原因进入有限修订或终止。

不可比、工具不支持、预算耗尽和运行异常是不同状态。不能为了贯通流程，把它们都退化为“让大模型再生成一段更强的 prompt”。

## 16 最小但能决定方向的实验

### 16.1 开发集与正式集分离

先用 4 至 6 对既有开发样本建立完整闭环，覆盖典型差异、困难局部控制和高光/阴影情形。若既有 c03 确属同一任务域，可以纳入困难开发样本；若与实际前置数据不同，只能作为额外压力样例，不替代正式域样本。

正式 20 对成对前置图保留为冻结评测集。不能在这 20 对上反复调参再报告泛化效果。数据不足时明确标为开发验证，待新保留集再下结论。

### 16.2 两个主要实验臂

G：当前已知较强、可复现的直接参考 Qwen 编辑配置。冻结模型版本、输入、参考、prompt 构造、输出尺寸与随机设置；不能为了突出新方案临时换弱基线。

T：本方案的自动摄影师式 Agent，加程序测量、数值求解与 PhotoCraft 执行。固定 VLM、操作集合、预算和验收规则。

A 原图始终展示，是不编辑参照，但不需要把它包装成另一个昂贵实验臂。若当前强基线没有可靠冻结记录，先补记录，不直接以某次记忆中的好图比较。

两臂使用相同 A/B 和同一参考目标定义。生成基线可以保留其原本合理的执行机制，不必被强制改造为工具臂；任何额外人工输入对哪一臂可见必须公开。

### 16.3 公平处理分辨率和预算

主观风格比较使用共同展示尺度，避免单纯大图占优；内容和局部缺陷另在各自原生输出上查看。生成模型若不能输出源图原生尺寸，明确算交付能力差异，不能通过放大隐藏。

分别报告质量和实际耗时/调用成本，不强求两种本质不同的执行机制渲染次数相等。预先固定各自合理预算，不做事后挑最好候选。

若生成基线存在明显随机性，正式实验固定一个预登记 seed，并在少量已指定样本上检查第二 seed 的稳定性；不将多个 seed 当作额外独立案例，也不进行无界 best-of-N。

### 16.4 开发阶段只做一个完整闭环演示

每例展示 A、B、G、T，列出关键目标、实际操作、前后量化差异、原生局部缺陷和人审结论。先确认“系统真的按参考修出了图”，而不是先做全部模块的单独准确率表。

开发阶段可以修正明显工程问题。每次修订要说明改变了哪种能力，不能用不断更换样例掩盖困难情况。

### 16.5 按失败触发的诊断

只有当主线失败且会影响下一步决策时，追加一种针对性诊断：

- 怀疑掩膜/对应错误：在同一失败例使用人工确认区域，保留工具和目标。
- 怀疑规划能力：有经验修图者用同一工具集合、同一目标和可记录的操作完成编辑。
- 怀疑工具表达不足：先证明合理目标与较充分的人工/数值求解仍达不到，再评估扩展操作；不能从 Agent 一次失败得出工具上限。
- 怀疑目标指标失真：统计改善而人审不认可，检查遗漏的关系和感知条件，不继续强压统计误差。

人工修图者输出是可达性证据，不是自动系统成绩。没实际请人完成时，不得写“专家也做不到”。

## 17 判定标准与下一步分岔

### 17.1 开发阶段进入正式评测的门槛

- PhotoCraft 核心接口、无操作路径、蒙版和原生导出验证通过。
- 至少多个开发例得到可重放结果，且不是只有一个偶然好例。
- 内容硬失败没有被验收系统漏放。
- 人审认为主要目标确实变得更接近 B，而非仅整体更亮。
- 目标合同、候选选择和失败回退工作正常。

不预先发明一个未经校准的统一 ΔE 或亮度误差阈值。开发阶段根据测量噪声、有效支持和用户可感知容差，形成每类目标的容差，再冻结到正式评测。

### 17.2 正式报告的核心结果

以 20 对图像为单位，报告：G/T 各自任务完成数、部分改善数、内容硬失败数、交付失败数；两者配对的赢/平/输；关键失败类型；单例和总体耗时。

同时给出逐例结果，必要时给二项比例区间或成对 bootstrap 区间，但明确小样本仅支持本任务域的方向判断，不支撑广泛模型排名。

不把“差异不显著”写成“两种路线等效”，也不把 20 个案例的平均统计改善写成摄影风格已经被完整建模。

### 17.3 四类决定

1. T 的参考匹配不差、内容保持更好，且多例可重放：继续发展工具式路线，重点改善自动区域与效率。
2. 人工使用同一工具可以完成，T 不能：优先修大模型规划、目标表达与搜索控制，不急着换生成模型。
3. 目标合理且工具确有表达缺口：只扩展决定性的工具能力，或再评估生成提案/局部生成方案。
4. 数值越来越接近，人审却不认可：重构目标与验收；继续增加统计指标或搜索次数可能无效。

若 G 和 T 都失败，不能宣布新路线无价值或旧路线最好；应先确定参考目标本身是否可达、是否有足够可比证据。

## 19 可复现性和安全边界

内部保存输入哈希、代码提交、依赖版本、模型版本与设置、色彩处理、掩膜哈希、合同哈希、操作序列、参数、随机设置、候选排名、导出元数据、耗时和错误日志。

保存完整原始 A，不覆盖原图；输出与报告分目录。照片不上传到新的第三方服务，除非已有明确授权；如 VLM 或 PhotoCraft 具体接入引入新的外部传输，先确认数据流与权限。

工具计划仅允许白名单动作和路径，不接受模型生成的任意系统命令。读取参考图不是允许复制其内容，执行修图也不是允许生成未授权结构。

内部可以保留图像、JSON 和日志，但用户回传只要求一份文本报告。若用户只回传文字，后续结论必须标为报告证据，不声称已独立看过图像。

## 20 主要风险与处理原则

| 风险 | 可能误判 | 处理 |
|---|---|---|
| 同场景但局部光照或姿态变化 | 把内容差异当作风格差异 | 双侧区域、可比等级、弱约束或排除 |
| 色彩编码不一致 | 数值“准确”但物理含义错误 | 统一色彩管理，记录假设 |
| 自动掩膜边界错误 | 局部调色看似不自然，误怪工具 | 原生边缘检查，按需人工诊断 |
| 指标不完整 | 统计达标但观感不匹配 | 独立感知目标与人审 |
| 操作能力不足 | 增加 prompt 无法解决 | 人工同工具可达性检查，有限扩展 |
| 搜索参数互相抵消 | 耗时高、重放脆弱 | 小工具集、低维参数、正则和固定顺序 |
| 预览与原生不一致 | 小图好、大图光晕或细节损坏 | 原生渲染和局部验收 |
| PhotoCraft alpha 变动 | 接口或数值行为漂移 | 固定提交，能力契约与回归测试 |
| 评审对新方案有期待 | 主观胜率偏高 | 匿名随机、分项判断、保留分歧 |
| 开发集泄漏正式集 | 小样本过拟合当成泛化 | 先划分，冻结后只评一次 |
