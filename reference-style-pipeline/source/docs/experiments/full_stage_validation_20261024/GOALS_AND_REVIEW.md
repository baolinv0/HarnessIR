# 项目目标与实验充分性审查

日期：2026-10-24。源码核查基于 `8636e25ad68dcb309961241bb9da454ed7ef0347`；前一文档提交 `e54c2b94b307f568628e326064cf0a3d1b36102d` 未改运行代码。此次为文档与实验设计更新。

## 1. 目标与边界

输入 A 是 Neural ISP prediction / 待增强照片，B 是外观参考。目标是学习可比区域的亮度、色彩、影调及区域间关系，同时保持 A 的内容与构图。B 不作为像素 GT，视角、物体和物理光照差异不能直接复制。

项目包含两个可分别验收的目标：

- 工具功能：每阶段可独立运行多个适用模型、保留原始结果、比较与可视化，选择明确的上游继续运行，失败可以定位和重放。
- 方法有效性：找出诊断、规划、编译、执行、判别的具体能力边界；比较共享规划和针对编辑器的规划，在当前任务上是否改善结果与成本。

D/P/J 的模型是 Qwen3.8-27B、Qwen3-VL-32B-Instruct、Qwen3-VL-8B-Instruct；C/E 的模型/路径是 FLUX 3 Klein/PUP、Fibo 2.0/VGL、Qwen-Image-2.1/PE-I2I、FireRed 1.1/Recaption。两类角色不能混成同一模型排行榜。

当前 profiles 是静态规划指南；路由依靠用户选模型/阶段。测试计划不能验证尚未实现的自动能力学习、自动路由、多轮反馈优化。若今后新增这些功能，需要独立版本和实验。

## 2. 原方案是否足够：不够，主要目标覆盖缺失

| 目标 | 原 VLM 校准计划 | 问题 | 完整计划的补充 |
|---|---|---|---|
| 五阶段单独运行、可视化和复用 | 有命令，缺完整项目验收 | 结果好不代表工具链正确 | F0 功能验收 |
| D 语义差异理解 | 基本覆盖 | obs 数不能代表准确率 | 事实审核、遗漏、可比性、随机性 |
| P 对不同 editor 的适配 | 只用 qwen21 profile | 没测模型专属规划 | 同 D/同 planner，generic 对四 profile |
| C 是否保留意图 | 基本没有 | C 丢信息易被误归因 E | 人工已知意图、native 条件逐条审计 |
| E 四模型能力与 Harness 增益 | 可选 Qwen 12 张 | 缺 FLUX/Fibo/FireRed 和公平原生基线 | N/G/M 主矩阵 + I 独立 C/E |
| 是否真正利用 B | 只看输出相似性 | 好看也可能忽略参考 | 固定 native 条件替换 B，单独检查 E 的参考响应 |
| J 能否判断真实生成错误 | 只有构造候选 | 不覆盖模型实际生成缺陷 | 控制候选 + 全模型真实输出固定子集 |
| 失败归因与复现 | 不完整 | 无法定位 P 文本、C、E 的边界 | D→actions→edit_prompt→C→E→J 的 lineage |

原方案适合作为调用配置校准，不能写成完整项目验证通过。本次修正范围，不否定已有校准结果。

## 3. 从源码确认的具体限制

定位文件均位于 `engine/src/hre/stage_lab/`，可通过函数名查阅：

1. `native_workers.instruction` 优先使用 P.edit_prompt，不会自动传完全部 actions/region_relations/preserve。必须审计 actions→edit_prompt→C 三份内容。前一步文本遗漏不能算编译器错误。
2. `compiled_condition` 不校验编译模型与编辑器配对；CLI 多来源、多模型默认产生笛卡尔积。E 逐个绑定对应 C，不能四个 C 同时交给四个 editor。
3. FLUX 有 C 时默认不再 PUP，可显式开回去；实验 E 固定 `use_pup=false`。Fibo 无 C 会自动 VGL，Qwen/FireRed 无 C 却不会自动 PE/Recaption。所有主臂显式 C 后 E，防止隐藏路径不一致。
4. `_canvas` 接受 Qwen PE 的 image2 或新比例建议，没有强制 A。预先按 A 的比例确定合法 width/height，四臂同样设置，另记 PE 原始画布建议是否错误；这是固定画布运行策略，不能伪装成编译器正确。
5. FLUX PUP、FireRed Recaption 的 worker 未透传 seed，不能假定所有 C 确定性。每份 C 仅编译一次、冻结，再执行两个图像 seed。
6. Fibo 当前 A+B+Mask 路径明确拒绝；FireRed 没实现单图 ROI 裁切编辑再融合；FLUX BBox 不等于硬 Mask。主实验只测当前全图 A/B 路径，不把文字中的区域目标称为空间硬控制。
7. 原生 C 没有统一 action_delta，审计表需单独填写。core 的亮度、尺寸、RGB 变化仅为描述统计，不能当质量分。
8. 默认 J 去掉上游信息；action 模式是独立检查。模型参数与实际响应应取证，OpenAI provider 当前未存完整 raw response/reasoning；按旧计划补日志或填可得字段，不虚构 token 统计。
9. Fibo/FireRed 编译器可能调用另一个服务；compiler 模型、费用与数据流必须计入。仅有权重不保证离线编译链已配好。

## 4. 什么证据足以验收

| 结论 | 最少证据 | 本方案能否回答 |
|---|---|---|
| 测试台五阶段功能可用 | F0 真正保存/复用/导入导出/错误记录/HTML，四真实 C/E smoke | 可以，须服务器执行 |
| 这个配置能稳定完成 D/P/J | 正确解析 + 人工事实/动作/判别审核，不仅 run status | 可以，限当前样本 |
| 某 C 会丢失或新增目标 | 已知 I、实际 compiler 输入、native 输出的逐项对应 | 可以 |
| 某 E 对正确条件仍执行不足 | I 的 C 合格而 E 两 seed 未执行，或修复 C 后仍失败 | 可以定位失败候选，不能据此判能力上限 |
| Model-Aware 比 generic 有益 | 同 D/planner、同 C 路径、同 E 配方下 M−G 的逐例比较 | 可以，属于 profile-conditioned planning 整体增益 |
| 完整 Harness 比原生路径有益 | 每个模型 M−N，同时看参考跟随和保真 | 可以，不是仅 compiler 的因果收益 |
| 模型使用 B | 固定 A/native 条件/E seed，B1→B2 的输出方向响应 | 可以测 E 在固定条件下的响应；若条件已写死 B1 外观，无响应不能推出完全忽略 B |
| Judge 可靠 | 控制图已知标签 + 真实结果人工盲审 | 可以评估典型错误；不保证自动放行安全 |
| 全场景最佳模型、显著领先、最佳 native recipe | 大样本/独立数据/充分配方优化 | 不能，当前不追求 |

如果某能力或模型未跑，表中写 NOT_RUN/BLOCKED，其余模型继续。四模型都完成对应实验后才可称“四模型比较完成”。发现明确错误、收益或无收益都属于有效实验结论；不要求为了获得正结果持续调参。

## 5. 审查记录

本轮主审依据源码与原计划检查；另两位同模型家族的只读审查 agent 分别核查 C/E 协议和实验覆盖，意见已合并。该审查用于发现遗漏，不是跨模型独立科学验收，也不是服务器真实模型验证。

补充结论边界：本轮固定一个 D_shared，不能单独证明“更换 D 模型导致最终收益”；profile P 仅覆盖选定 planner，其余 VLM 只比较 generic P。参考响应主检查固定 C，避免无 seed 的 compiler 重采样混杂。
