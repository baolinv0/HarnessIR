# 完整五阶段实验计划

版本 1.0｜2026-10-24｜运行分支 `feat/stage-model-lab-20261022`。
目标：独立测 D/P/C/E/J，比较四个编辑模型的适配效果，并把最终差异定位到具体阶段。

## 1. 决策问题和对照

Q1：模型能否发现真实且相关的 A/B 差异，转为合理 action，再无歧义地交给原生编辑器执行？
Q2：共享规划或模型专属规划，相对每个编辑器自己的原生路径，是否改善参考属性跟随、内容保真及区域协调？Judge 能否正确识别这些结果？

默认不训练、不自动多轮重试、不做大规模参数网格。此前温度配置结果可复用；先使用已跑通且日志完整的 VLM 配方。不要将七个温度臂乘到四个图像编辑器上。

## 2. 固定数据、意图和评价

从旧计划 hold01–04 复用四对 A/B，或用下表重新登记四对；固定 case_id、原图 SHA、任务、显示方向、分辨率和可比区域。若这些图参与过配置选择，明确为工程开发验证集，不继续称独立 holdout。

| case | 场景要求 | 要检验的困难 |
|---|---|---|
| c01 | 全局亮度/色彩/影调差异，内容较可比 | 全局参考跟随与颜色方向 |
| c02 | 主体局部曝光或颜色差异 | 改对目标区域，非目标不过度改变 |
| c03 | 前背景明暗/肤色/高光协调 | 关系目标，不是单独提亮每个区域 |
| c04 | 构图/视角有差异但局部可比 | 不复制 B 内容、不错误裁切 A |

同一个 case 使用同一内容锚点 A，图片先统一 EXIF 方向；记录原始版和送入版 SHA。需要适配尺寸时，保比例 resize/pad，记录比例与 pad，不裁切关键内容。所有模型用同一送入 A/B；各模型内部缩放/输出合法尺寸另记。禁止把模型输出 resize 后覆盖原始生成文件。

每 case 先由人工冻结：4–8 条可核实关键事实、目标 ROI、非目标/保护 ROI、人工参考意图 I。I 不是唯一审美真值，而是清晰、可行、便于检查的一个已知编辑任务。指定 1–3 个目标属性及方向、区域关系、允许改变与必须保留内容；A/B ROI 坐标分别记录，可比性分 full/partial/noncomparable。禁止用不对齐的 A/B PSNR 当效果指标。

主臂的质量评价针对同一 case-level 任务和人工基准，不能让每个 planner 自己定义成功标准。action 完成度另报，完成一个不合理 action 不算质量改善。

## 3. F0：工具与原生路径验收

先用 CPU demo/已有协议测试检查工具，再用真实权重确认四模型 C/E。下表每项填证据文件或界面截图；模拟结果仅证明工具行为。

| 功能 | 执行方法 | 通过条件 |
|---|---|---|
| 独立 D/P | A/B 直接 D；手写 observations 直接 P | 无需先跑其他阶段，输入/输出可查 |
| 独立 C/E | 人工 I 直接 C；指定 condition 直接 E | 没有隐式重新 D/P/C |
| 独立 J | 导入外部 C 候选直接 J | A/B/C 角色与候选 SHA 正确 |
| 模型比较 | 同 case 同阶段至少两模型 | 独立 run，HTML/界面并排可读 |
| 上游复用 | 保存结果后重启程序，再按 run_id 使用 | 指向原文件/原条件，不重新生成 |
| 失败可见 | 单独配置不存在的 command 或不可用本地 endpoint | 留下错误，其他运行仍可完成 |
| 手动导入/导出 | 导出一个请求，原样导入已知结果 | 路径可解析、来源与 manual 身份可见 |
| 可视化与追溯 | HTML 按 case/stage/model 筛选，查看 A/C 与原始 JSON | 每张图可查 D/P/C/E/J 来源 |
| 四原生 C/E | 每模型在 c01 的 N 臂先跑 C、E seed42 | 真调用、有 native condition/图，不是 demo |

四次真实 smoke 若所有条件与正式 N 相同，可计入主矩阵，无需重复。编译器缺依赖、权重、服务或接口不兼容时记录失败，先修该模型接口；其他模型继续。不能用另一个模型替代后仍沿用原标签。

## 4. D：差异诊断与共享观察

四 case × 三 VLM × 两 seed17/29 = 24 次；可从旧计划等条件结果复用。固定 D prompt，不限制恰好几条观察。审核 supported/contradicted/unverifiable、去重、关键事实覆盖、可比性和区域关系。协议失败用 NA，不假装 obs=0；JSON 合法和视觉正确分开。

先按诊断准确性与成本选定 D 配方。为每 case 取该配方 seed17 的结果，保存为 D_shared；若 seed17 失败则记录失败与后续重跑编号，不挑最好描述。清除送给 planner 的模型名称/自评分，原始来源留在 ledger。

在当前四例选择 D 属于工程选型，不能再把后续四例说成完全独立验证。需要泛化结论再另加新图，本轮不强制扩样。

## 5. P：独立比较与模型专属规划

### P-isolated

使用相同 D_shared + A/B + generic profile，四 case × 三 VLM × seed17 = 12 次。三个模型看同样的诊断，可纠正或拒绝错误观察。按 action 的证据、目标区域、方向、关系、内容保护与冲突选定一个 planner。

选定 planner 的 generic P 即 G。每 case 一份冻结 G，之后四个编辑器使用同一份，不能分别润色。

### P-model-aware

同一 D_shared、同一 planner/seed17/采样，分别指定 flux3_klein、fibo2、qwen21、firered11，四 case × 四 profile = 16 次，构成 M。模型特定 P 可以调整动作优先级和表达，但不能修改任务基本目标或放弃关键目标后自称成功。

保存 `actions[]`、region_relations、preserve、rejected_observations、edit_prompt。逐项检查 action→edit_prompt 的信息损失。本分支 C 主要读取 edit_prompt；如果结构化 action 有而文本没有，定位 P 的表达/交接，不归因 C。

范围说明：三个 VLM 都接受 generic P 比较，只有选定 planner 运行四种 profile；不能声称三者都完成了全 profile 比较。

G 与 M 先按原始输出执行，不人工挑改。明显不合理也保留错误证据；人工修正后若再执行，标新 R 臂，不覆盖原结果。

## 6. N / I / G / M 四种条件

| 臂 | 来源 | 固定与变化 | 回答的问题 |
|---|---|---|---|
| N | 同一简洁参考增强任务，明确 A/B 角色 | 无 D/P；使用该编辑器既定原生 C→E | 当前原生路径基线 |
| I | 预先人工核对的已知 action 与 edit_prompt | 同一 I 给四 C/E，绕过 D/P | 编译与执行的独立能力 |
| G | D_shared→选定 planner，generic profile | 每 case 同一 P 给四 C/E | 共享分析/规划是否有用 |
| M | 同 D、同 planner，目标 editor profile | 每个编辑器自己的 P，同样 C/E 配方 | 模型专属规划是否有用 |

主效果比较 N/G/M：4 case×4 editor×3 arm×2 seed=96 张。
独立 I 的 C/E：4×4×1×2=32 张。I 是人工已知输入探针，不宣称人工方案最优，也不把人工收益算成 Agent 收益。

差值解释：G−N = 共享 D/P 策略整体收益；M−G = profile-conditioned planning 整体收益；M−N = 本次 Harness 整体收益。M 可能同时改变动作与措辞，不能把差值说成仅格式优化；固定 G/I 跨模型是 C+E 路径对比，不能凭跨模型分数单独分离 C 与 E 的因果贡献。

## 7. C：模型原生编译，必跑

四模型各臂使用相同原生 C 配方，所有 C 显式保存；64 个 case/editor/arm 组合各编译一次。C 可有随机性，只保存预定第一次有效响应；网络错误可重试且计成本，语义错误不挑样。

| editor | 主计划 C | E | 需要固定 |
|---|---|---|---|
| flux3 | 官方 PUP (A/B+instruction) | FLUX 3 Klein | 模板/权重 SHA，E use_pup=false |
| fibo2 | bria-vgl.modify(EditImages) | BriaFibo2Pipeline | VGL 原生结构、compiler LLM/采样/费用 |
| qwen21 | PE-I2I | QwenImage21Pipeline | PE 模板、ratio_follow/wh_ratio、显式 A 画布 |
| firered11 | 文本 Recaption | QwenImageEditPlusPipeline，1.1 权重 | Recaption 后端/模型，A/B 角色措辞 |

这里的 N 是“本次冻结的原生条件路径”，不声称原生最优。PUP/VGL 不是 Harness 新增收益。Qwen PE 与 FireRed Recaption 不是编辑必需步骤；本计划为覆盖 C 将其开启在 N/I/G/M 全部臂。如需要比较 direct，另做同模型 C-bypass 对照，不仅给 N 关闭。

若 PE/Recaption 无法运行，可以将该模型所有臂暂设 identity C（记录 native_prompt 不变）继续 E，但必须标明 native C NOT_RUN，不能据此称本计划四原生 C 验收完成。FLUX/Fibo 不用通用 VLM 伪造 Caption/VGL 来替代官方编译后宣称原生验证。

每份 C 保存：I/P action 原文、实际 compiler instruction、A/B SHA、C 参数/版本、最终原生条件与 SHA、额外模型及耗时。Fibo VGL 用结构化规范化 JSON 算语义哈希，同时保留原始字节哈希；其他模型保存实际字符串。

逐条审核动作映射：preserved / omitted / modified / added / unverifiable。区分合理扩写与有害改写；计算目标保留比例并列遗漏关键目标数、无根据新增目标数、A/B 角色错误、画布建议错误、格式可执行性。不得用字符串相似度代替语义忠实度。C 的 action_delta 由审计表填写，不假设原生输出自带。

## 8. E：真实生成与条件执行，必跑

每份冻结 C 用同一编辑器执行 seed42 和43，128 张。E 不再调用 D/P/C。两 seed 是同一编辑器内配对，不同模型相同 seed 数值并不是相同噪声。

先在 smoke 确定每个 editor 合适的推理配方，随后 N/I/G/M 固定 steps、CFG/true_cfg、checkpoint/量化、输入和输出尺寸策略。不同 editor 不强行同 CFG/steps；汇报实际速度/显存/费用。编译配置一次固定，同一 C 跨 E seed 复用。

Qwen 按 A 比例预先设置合法 width/height；保留 PE 原始画布输出用于 C 评分。其他模型同样采用预先定义的 A 画布策略并记录实际尺寸。若某模型不能保持该画布，保留原图并报告能力差异，不能事后裁切到看似相同。必要的评价缩放另存 eval copy，不能声称像素未变。

E 条件一致性：保存 E 实际收到的 prompt/VGL SHA，与对应 C 比较；手动确认 compile_run 与 editor 匹配。不要把多个 C_RUN 和多个 E_MODEL 在一条 CLI 中交叉传入。

### E 评价（人审所有 128 张）

先隐藏模型、臂和 action，统一显示 A/B/候选，按相同 case-level 目标判断；再展示 action 做完成度审计。另8张B2同样人工审核，总计136张。每项给 evidence ROI，可用 improved/unchanged/worse/uncertain 或 pass/fail/uncertain：

1. 参考属性跟随：目标区域的明暗/色相/饱和度/高光层次方向，非全图“像不像”。
2. 内容保真：文字、人物、物体形状、纹理与构图变化，记录严重内容错误。
3. 区域协调：前背景相对亮度、肤色与环境颜色、局部过渡/光晕。
4. action 完成：每个实际 action 达成/未达成/过度/不确定；不替代第1–3项。

同尺寸同构图的 A/C ROI 可测亮度分位数 p10/p50/p90、剪切比例、颜色方向与区域间差值；注明基于显示 RGB 的描述性统计，不当物理曝光/色温真值。A/B 仅在可比 ROI 比较趋势。没有色彩管理不要强行把 RGB 差写成精确 ΔE。全局直方图容易被裁切/内容占比误导。

M/G 对 N 的人工成对胜负按 case×seed 列出，允许 tie/uncertain；四 case 平均时先聚合两 seed，不能把八张当八个独立场景。任何“更亮更像 B”伴随严重身份/文字/结构错误，必须单列，不能被平均美学分抵消。盲审时只显示blind_id与A/B/候选，CSV中的editor/arm/seed在判定后按映射回填；不能让表头元数据泄露身份。至少一位人审；有第二人时复核所有重大错误和分歧，记录人数，不以 VLM 多数票当真值。

## 9. E 的图像参考响应检查（新增 0 C + 8 E）

预先选 c01，不根据输出挑案例。保留 A，基于同一 B1 构造 B2：只做一种可测、无剪切、明显可见的颜色或影调改变，保持内容/几何完全相同。记录确定性变换参数、B2 SHA、人工确认的预期响应方向；不要求 B2 更好看。

**复用 B1 的 N 臂原生 condition，A/condition/E参数/配对seed均相同，只替换 E 的参考图片 B1→B2。** 四 editor 各执行 seed42/43，新增8张；B1已有的8张主矩阵N结果直接复用。不重新调用 C，避免 PUP/Recaption 未固定采样带来的混杂。新case使用 context.condition 载入原始条件并记录 source C ID/SHA，不跨case使用 --from-run。

检查输出在可比目标区域是否按预期方向响应、是否引入内容错误。这里测 **E在给定原生条件下是否响应图像B**。如果 C 已把 B1 的颜色/影调写得很具体，B2与文本会冲突：此时无响应可能是文本优先，不能推断模型完全不用B；报告必须标记 condition 是否锁定 B1 外观。默认不据此比较四模型“利用B强弱”排名。

若需要另看全路径参考响应，可单列探索性条件：B2重新C后E，并保留C变化。当前FLUX/FireRed C未完全控制随机性，该额外结果只能提供全路径响应线索，不能声称唯一变化是B；此项不在核心预算中。FireRed Recaption为纯文本，任务文字相同时通常无需重采样。

## 10. J：已知控制 + 真实图像判别

### J-control：27 次

沿用旧方案三个 case×C0=A、C1=确定性温和调整、C2=C1+已知可见内容损坏×三 VLM。操作标签对模型隐藏；记录 unchanged 假改善、损坏检出和调整方向。C1 不自动是正例。

根据这部分表现确定主要 Judge J_star；使用已有三配方，不为 J 偷看最终图后调参数。

### J-real：192 次

对主矩阵 128 张，J_star 全部评价。另两 VLM 在预先固定的 N/M seed42 子集全部评价：4 case×4 editor×2 arm=32 张，各32次，总64次。这样三 Judge 在完全同样32张真实输出上横向比较；其余96张不声称已有三模型对照。

参考响应检查的8张新增图交 J_star，再8次。J 合计=27+192+8=227 次（可复用已有等条件控制结果）。所有真实图片由人工审核，不只审“模型意见不一致”的图。

默认 J 只给 A/B/C 与原始任务，隐藏 D/P/C 文本、模型/臂、人工标签。报告 reference_alignment/content_preservation/coordination 分项，不能把 content 中的解释长度当准确性。

真实结果与人工比：方向判错、漏检内容损坏、虚构缺陷、区域关系误判；可报告“人工明确判 fail 而 Judge 判 pass”的假接受，及相反假拒绝，分母只含该项人工确定样本；uncertain 另列。没有定义自动 pass 阈值时，不造综合假接受率。多人分歧保留，不强制合成唯一分数。

## 11. 失败归因与最小追加实验

本矩阵只有一个 D_shared，G−N测D/P整体策略，不能直接归因为“27B多发现事实导致图片改善”。若确实需要该结论，再预先选2个case，比较两份不同D来源→同一个planner/profile→同一C/E配方×两E seed；可复用其中一臂，其余作为额外实验单列。否则保留诊断事实与下游行为的案例分析，不写成已隔离D效应。


| 现象 | 首先检查 | 合理定位 |
|---|---|---|
| 事实未看见/看错 | D 原图证据 | D |
| 事实正确却 action 错 | P 采纳与关系目标 | P 决策 |
| action 有但 edit_prompt 无 | P 输出三份对照 | P 表达/交接 |
| compiler 输入正确、条件错误 | C 条件审计 | C |
| C 正确，E 不执行 | 两 seed 和 I probe | E 执行不足候选 |
| 图有问题，Judge 没发现 | 人审 ROI 与 J 输入尺寸 | J 或视觉输入信息不足 |

关键坏 C 如阻断归因，可做 R 修正臂：只修有证据的那个 native 条件，保留所有其他 E 参数、原 seed 与原失败结果。最多先选2个 case/editor 失败单元（2 seed，各共4张），不混入 N/G/M 主表。若条件修好明显改善，支持 C 瓶颈；仍不改善只支持当前设置下 E 不足，不证明模型能力上限。

不用为了“完成矩阵”把所有负结果重跑到成功。缺样本记失败；生成过程重试计入实际成本。没有进入 GPU 的接口错误和真正生成后的质量失败分开。

## 12. 预算、顺序与结束标准

| 部分 | 计划量 | 可复用 |
|---|---:|---|
| F0 | CPU/接口检查 + 4 模型 smoke | smoke 计入 N c01 seed42 |
| D | 24 VLM | 旧计划等条件结果 |
| P | 12 generic + 16 profile = 28 VLM | 选定 generic 输出直接作 G |
| C | 64 原生编译，B2复用已有条件 | 每份一次冻结 |
| E | 96 主矩阵 + 32 I + 8 B2 = 136 张 | 不选最好 seed |
| J | 27 控制 + 192 真实 + 8 B2 = 227 VLM | 旧控制可复用 |
| 可选 R | 最多先4张 | 只用于定位失败 |

基础 VLM D/P/J 合计279次；64次 C 若内部另调用 LLM，调用数/token/费用单列，不能算零。初始化/模型加载/预热/失败重试另计。不要把旧100次与本表机械相加；等条件重用要有原 run_id。时间用 smoke 实测 C/E秒数×未完成数量按模型求和估算，报告设备并发与GPU占用，不虚构固定小时数。

顺序：F0 → D → P → 每模型先 c01 的 N/I/G/M seed42 检查数据链 → 其余 C/E seed42 → seed43 → B2 → J-real/人审 → 汇总。J-control 可在 E 前执行。按模型分批加载，冻结条件后可并行 E，不要求四模型同时驻留。

结束标准：五阶段功能有证据；四模型 C/E 各有真实状态（成功/失败明确）；N/G/M 和 I 的结论分开；J 有真实候选核对；每个重点结论可定位 run、条件与图片。接口、模型能力或策略无收益均可成为结论。只有一个模型没完成时报告“三模型已完成/第四阻塞”，不能写四模型完成。

## 13. 可视化和回传

每阶段独立页面/表：D 的事实共同/独有/冲突；P 的观察→action→文本；C 的 input→原生 condition 的语义变化及 Fibo 字段 diff；E 每 case/seed 的4 editor×N/I/G/M图，提供全图和相同语义ROI放大；J 同图三模型判断与人工证据。原始尺寸展示与统一大小预览分开标注。

Stage Lab HTML 支持原始结果查看、文本 diff、图片与筛选；人工语义审计、统计表、lineage.csv 由执行人员填，不声称项目自动生成了全部指标。以本目录 REPORT_TEMPLATE.md 回传完整报告，附所有成功/失败 run、请求与参数、原生条件、图片、HTML、人工表及原始/评估图映射。
