# 工程师交接：原始 HarnessIR 五模型实验

日期：2026-10-24 · 版本：v1.1（单文件回传）

目标：保留原始五阶段，将图像执行器替换为五个开放权重编辑工作流，并验证必要模块适配的收益。

## 按此顺序使用

1. 阅读 `EXPERIMENT_PLAN.md` 第0–7节，固定任务、基线、五模型profile、D/O/A变量与数据。
2. 完成原executor工厂、原生adapter、Compose/Refine表达profile与日志。可复用已有四模型原生调用；不迁移控制器。
3. 完成E0部署检查和DEV；只有DEV允许调策略。冻结版本后跑TEST。
4. 执行E3固定池评价与E4一次反馈/重采样对照；有需要才开E2或第三候选。
5. 按 `REPORT_TEMPLATE.md` 回填一个 `REPORT.md`，直接复制粘贴回传；完整明细、图像、配置和实际执行条件留服务器。

## 文件说明

| 文件 | 用法 |
|---|---|
| `EXPERIMENT_PLAN.md` | 完整实验与最小工程规格 |
| `REPORT_TEMPLATE.md` | 五模型实验报告填写模板 |
| `EXPERIMENT_TRACKER.md` | 里程碑与各模型状态 |
| `run_matrix_template.csv` | 最终冻结版本650个计划生成位；尚未绑定真实数据，不是运行记录 |
| `manifest.template.json` | 数据清单草案；路径/任务/ROI必须补全 |
| `REVIEW_NOTES.md` | 方案审查范围、已修正风险与证据边界 |

## 三条主要比较

- O−D：原始HarnessIR相对同模型直接编辑。
- A−O：同模型、同事实/工具/原生compiler下的表达适配。
- F−S：相同额外候选预算下，一次反馈改写相对固定条件重采样。

核心最终版本计划：E0最多15次，DEV150次，TEST300次，反馈新增200次，共最多665次图像调用。实际部署失败、探索版本和重跑另计，不宣称硬性封顶全部开发工作。E3复用图像但消耗VLM/人工；可选机制、文字或第三候选另有独立预算。

路径和JSON字段为交接模板，工程师须映射到现有RunConfig/manifest；本包不声称存在新的CLI命令或已实现的配置schema。所有结果均为待运行，未调用正式图像模型。

报告默认只有一个文件。CSV、JSON和跟踪表是工程师在服务器的辅助材料，不是用户必须回传的附件。没有可读取图像时，接收方只能检查文档证据和推断一致性，不能独立验证画质。
