## 0. 一页决策摘要

**本实验的主对照回答一个工程问题：官方 PE-I2I 是否值得成为 Qwen 版 HarnessIR 的默认指令出口；若值得，应替代 Compose，还是接在 Compose 后面？**

实验目标不是让 Prompt 更长、更专业，也不是仅提高 IQA。最终目标是：尽量消除整幅图像的明显退化；对证据不足的严重损坏区域允许合理生成性补全，但不得改变可辨认的重要内容，不得产生明显不合理的几何、文字或材质。

采用四个核心条件：

| ID | 路径 | 检验问题 |
|---|---|---|
| A0 / Raw | 原始恢复指令 → Qwen | 简单指令基线 |
| A1 / Raw+PE | 原图 + 同一恢复指令 → 官方 PE-I2I → Qwen | 官方原生改写是否改善简单指令 |
| B0 / Compose | 冻结 HarnessIR Compose 输出 → Qwen | 当前被研究的系统指令基线 |
| B1 / Compose+PE | 原图 + B0 的逐字相同指令 → 官方 PE-I2I → Qwen | PE 能否改善既有系统指令 |

**保留 C0：现有最强简洁指令路径（compact 或经核验的现行候选）作为采用决策对照。** 若 C0 与 B0 完全相同，则合并，不重复生成。PE 只胜过较弱的旧 Compose，不足以证明值得上线。

主实验：沿用现有 25 图做回归比较，2 个生成 seed。最多 250 张主条件输出；加 20 张重写稳定性输出、20 张显式恢复意图诊断输出、最多 4 张历史复用审计输出，共最多 294 个预定图像生成作业。四臂合并版为 244 个。PE 改写共 75 次。能够严格核对的历史输出直接复用，不强制重跑。

本轮不训练，不引入参考图、不换执行器、不做局部裁块或区域拼接、不联合修改 Verifier、不增加多轮恢复。先隔离“指令出口”的作用。第 12A 节的反馈搜索、保留描述消融与 FLUX 对照为条件触发的后续方案，不进入本轮默认预算。

### v1.1 修订摘要

本版保留 v1.0 的主条件、历史可比性与参数设置。新增的是：①5 张开发图上的显式意图 × PE 小对照；②目标属性、保留描述及生成补全的文本—图像追踪；③训练机制与运行时搜索的推断边界。原计划中“只在评价端允许合理补全”的设置，不再被当成已测试“PE 能否传达该意图”。FLUX PUP 的训练方法仅作为依据和后续启发，不被写成 Qwen 的已知训练方式。

## 1. 依据、修正与推断边界

### 1.1 已核对的官方机制

官方 PE-I2I 是单独的编辑指令改写 checkpoint，使用原图和指令，输出重写文本及画布相关字段。不能用通用 Qwen 27B 加一段 system prompt 冒充“官方 PE”；这种替代品必须作为另一种方法。[S1–S3]

官方规则不仅强调保持未编辑内容，还明确反对 under-editing：内容保持不应削弱所要求的编辑强度。因此，本计划不预设“PE 会更保守”，也不预设“PE 一定能激活恢复能力”。两种结果均允许出现。[S2]

PE 本身也会看图。因此 A1−A0 测量的是“增加官方视觉条件改写模块”的整体效果，不是纯文字润色、不只是长度变化，也不证明专门微调比通用 VLM 更好。

官方规则还要求：不要过度描述未修改内容的外观；不要主动修复用户未要求的其他缺陷。因此，“充分执行已指定的属性”和“自动发现并修复全部退化”不是同一个目标。文本审计须区分目标没说清、PE 遗漏目标和实际图像未响应。[S2]

FLUX PUP 模型卡明确披露 SFT 后使用其候选 Prompt 在同一 FLUX seed 下渲染并按图像排序的偏好优化。本次可访问的 Qwen 官方改写 README 与系统规则未给出同样训练说明；这只代表披露不足，不证明 Qwen 没有采用图像反馈训练，也不证明它只优化文字质量。[S2,S3,S7]

### 1.2 已有实验如何使用

已有工程报告记录了 25 张夜景低光图，以及 6 张开发图上的 CFG×Prompt 对照。报告支持保留 cfg=4.0 作为现有工程对照配置，并将 compact 列为值得验收的候选；它不等于已完成独立视觉验证。[S4–S6]

本次仅核读这些报告与配置说明，未独立取得其全部原始输出、运行环境和逐图评分。服务器执行前以真实运行快照为准，不能把本计划中的历史摘要当成复现。

### 1.3 本轮能够与不能够下的结论

能够回答：固定执行器下 PE 是否改善输出；对 Raw 与 Compose 的效果是否不同；是否超过现有简洁路径；收益是否稳定；能否进入下一轮系统验收。

不能直接回答：Qwen 与 NB2 的架构能力差异；是否恢复了不可观测的真实纹理；长 Prompt 是否必然有害；效果是否能推广到全部 All-in-One 任务；线上真实风险是否为零。

## 2. 任务合同与成功定义

### 2.1 所有条件共享的目标

恢复整图可见的噪声、模糊、拖影和异常亮暗，使图像清楚、自然、协调。不能只修好一个显眼 ROI，却遗漏其他严重问题。

对严重损坏区域，允许补全与场景一致、没有明显视觉矛盾的纹理和轮廓。**“允许生成”不等于允许改变对象身份、数量、重要几何、遮挡关系或可可靠读出的文字。**

对无法确认的微小材质细节，允许记录为“合理但不可证实”；不得宣称是真实恢复。原本无法可靠辨认的文字，不应被补成具有确定含义的清晰字符串。

### 2.2 不把评价合同直接堆到每条 Prompt 后面

上述内容是跨组共同评价标准，不是统一追加的长约束尾巴。主实验保留已有 Raw 与 Compose 文本，避免为了测试 PE 同时重写所有基线。另设 P1-I，将该意图以短指令显式输入，仅作开发诊断；不能把主实验 U0 没说清的目标，事后当成 PE 应当逐项遵循却没有遵循的指令。

Raw 默认复用现有简单指令；若实际快照就是下面这句，原样使用：

> Restore this low-quality image to a clear, clean and natural state and recover its normal brightness.

实际历史文本与上句不同，以历史快照为准，在运行清单中逐字登记。中英文不互相翻译；不因某个条件效果差而逐图手改。

这个宽泛指令未明确列出所有恢复动作。PE 是否漏掉模糊、是否错误解释 normal brightness，本身就是本轮要观察的现象。v1.1 的 P1-I 在并行开发条件 E0/E1 中显式修改用户意图，主条件 U0 不变。任何后续全量替换 U0 的实验须另锁协议，旧、新文本结果不得混入同一条件。

---

### 2.3 属性范围与“编辑扩散”的判定

用 `(区域, 属性)` 而非只有“区域”定义允许改变的目标。例如：整图去噪与可见性改善、骑手去拖影属于授权改变；可辨身份、对象数量、重要几何和可靠文字属于内容不变量。全图恢复时，不能把每个未列 ROI 的像素变化都算成 edit leakage，也不能因为模糊消除而把外观变化算成内容错误。

合理补全仅适用于确实严重退化的区域。审计区分“未授权的新内容”“与场景一致但不可验证的普通纹理”“可靠内容改错”。前者和后者进入风险记录，中者不因缺少真值自动判失败。

## 3. 假设与对照关系

| 假设 | 必需比较 | 支持它的观察 | 不能据此推断 |
|---|---|---|---|
| H1：PE 可改善简单恢复指令 | A1 vs A0 | 恢复与可交付率改善，内容错误不增 | 所有图像或所有任务都有效 |
| H2：PE 可修复 Compose 表达 | B1 vs B0 | 同一 Compose 内容经过 PE 后输出改善 | 原问题一定只是 Prompt 长度 |
| H3：HarnessIR 提供的诊断仍有增量价值 | B1 vs A1 | 相同执行预算下 B1 稳定更好 | 增益一定来自诊断而非表达差异 |
| H4：PE 值得进入现有工程 | 预选 PE 候选 vs C0 | 超过现有最强可用路径，代价可接受 | 只胜过旧 Compose 即值得替换 |
| H5：收益不依赖一次幸运重写 | PE 重写重复试验 | 多次重写下方向稳定，无频繁严重回退 | 固定 seed 保证跨环境逐像素一致 |
| H6：明确的恢复意图可以被 PE 有效传达 | 开发集 E0/A0、E1/A1、E1/E0 | 指令表达和生成收益配合，内容错误不增 | 把全部收益归因于“允许补全”这一句话，或外推为已验证泛化 |

图像质量打分可计算交互量 `(B1−B0)−(A1−A0)`，用于描述 PE 对两类输入的影响差异。不得据此声称隔离了“纯长度”“诊断质量”或“训练数据”的因果作用。

## 4. 数据与划分

### 4.1 回归集合

优先复用已有 25 张夜景低光图，保留原样本 ID、来源、预处理后的文件和哈希。已有报告记录来源为 exDark 9 张、JarvisIR-Night 8 张、ACDC-Night 8 张，工程输入为 1024×1024。[S4]

本轮只检验这个低光/复合退化集合上的表现，不据此写成通用 All-in-One 性能提升。

### 4.2 调参暴露审计

对每张图标记：

- `DEV`：曾用于设计/修改 Prompt、调参数、挑方法，或本轮开发审计使用。
- `REGRESSION_ONLY`：已有输出或已看结果，用于回归评价，不称为严格独立测试。
- `HELDOUT`：运行前确认未用于这些决策，且同场景近重复图没有出现在开发集。

已有“五张开发图”和更早“六张开发图”应取历史使用并集，而不是只排除最近五张。若历史图 ID 无法核对，则不能把其余 20 张直接称为独立测试集。

建议本轮开发审计使用 5 张已用图，覆盖严重拖影、欠曝、文字/小物体、较轻退化、复合困难场景。`night_0043` 必须保留为严重拖影案例；其他图从既有开发图按覆盖选取，名单在出新图前冻结。

25 图仍可全部执行回归评价。真正的泛化结论需要另外保留至少 20 个未用于开发的独立场景；若当前无法获得，本轮照常完成回归实验，结论写“回归收益，独立验证待完成”，不为了填报告伪造测试独立性。本计划预算不包含额外新数据验收。

### 4.3 预先冻结问题清单

看输入图，不看本轮候选，为每图记录主要退化、3–5 个确实存在的问题 ROI、关键保护区域和优先级。少于 3 个明显问题时不凑数。

每个 ROI 包含：位置、问题、严重程度、期望改善、哪些事实可可靠判断。不要把不存在的细节写成恢复目标。评价 ROI 仅用于评估，不额外作为 mask 或裁剪条件送入执行器。

## 5. 条件定义与共用输入

设输入为 I，原始指令为 U，冻结的诊断/计划为 D，Compose 为 C。

| 条件 | 送给 PE 的内容 | 实际送给 Qwen 的正向 Prompt |
|---|---|---|
| A0 | 不调用 | U |
| A1 | I + U | `PE(I,U)` 的有效重写文本 |
| B0 | 不调用 | 冻结的 `C(I,U,D)` |
| B1 | I + B0 的逐字相同文本 | `PE(I,C(I,U,D))` 的有效重写文本 |
| C0 | 不调用 | 冻结的 compact/当前最强简洁路径输出 |

D、B0、C0 每张图只生成/读取一次并缓存，不随图像生成 seed 重做。优先直接复用可核验的已有产物。D 不得参考 A1/B1 的结果后再修改。

B0 指本轮明确选定的 Compose 版本，不混用原版、E1-P1 和其他分支。名称、代码版本及逐图文本必须写清。

C0 在看本轮结果前根据已有证据确定，不从新候选中挑最好者。如果 C0 与 B0 的逐图文本、执行配置完全相同，则合并两条件；否则保留 C0。

LQ 与已有 NB2-HarnessIR 输出仅作视觉锚点。NB2 输出不是像素真值，不用于拟合 Prompt；输入版本、模型版本、调用预算不明时，不计算正式公平胜率。

## 6. 固定参数与独立随机性

### 6.1 Qwen 执行器

| 参数 | 主实验约定 |
|---|---|
| 模型 | 现有 Qwen-Image-2.1 原始 checkpoint；不换 Turbo/Pro/其他版本 |
| 权重与代码 | 固定 revision、checkpoint manifest、pipeline/scheduler 配置 |
| 精度 | 沿用现有 bf16；所有条件一致 |
| 步数 | 40 |
| `true_cfg_scale` | 沿用已核查的 4.0 工程配置，不把官方默认悄悄混入 |
| `negative_prompt` | 沿用同一历史值；报告所述为单个空格 `" "` |
| 生成 seed | 0、42 |
| 输入/输出 | 历史预处理后的同一 1024×1024 输入；输出同尺寸；不追加缩放锐化 |
| 每条件每 seed | 只生成一次，不挑最好，不循环重试画质 |
| Verifier/回退/redo | 不参与生成或选图；离线记录允许，但不能改变被评估结果 |
| 缓存与优化 | 所有条件同设置；跨样本/条件缓存正确隔离，记录实际配置 |

必须记录实际调用参数名，而非只写“CFG=4”。已有配置核查报告区分了 `true_cfg_scale`、负提示条件与实际 CFG 分支。[S6]

不在本轮重新全量搜索 CFG。若后续在 cfg=1 做复核，应成对比较同一原始与 PE 条件，另开分析层，不与 cfg=4 合并均值。

### 6.2 PE-I2I

采用官方 edit checkpoint 与其配套 system prompt。系统指令、模型权重、tokenizer/processor/chat template 都固定版本与哈希。[S1,S3]

官方 edit 推理设置作为本轮默认：

| 参数 | 值 |
|---|---:|
| temperature | 1.0 |
| top_p | 0.95 |
| top_k | 20 |
| min_p | 0 |
| presence_penalty | 0 |
| max_new_tokens | 24000 |
| enable_thinking | true |
| 主重写 seed | 42 |

这些是 edit profile 的参数，不套用 T2I 的 presence penalty，也不直接套用现有 Qwen 27B 的 temperature=0.2。[S3]

首选离线批量运行 PE，缓存全部重写，再卸载 PE、运行图像执行器。单卡环境不用要求两模型常驻。若需要内存优化，所有 PE 条件统一、记录变更，不把 OOM 静默解释为模型能力差。

运行环境另行冻结：GPU 型号/数量、显存、驱动/CUDA、torch/diffusers/transformers/vLLM 版本、PE 后端、TP、graph/eager 模式、attention 实现与 offload/量化开关。不得一半条件切换后端或精度。PE 和生成器各自的输入缩放/像素预算应记录；给各条件的源图文件必须一致。

两个随机源独立：`rewrite_seed` 控制 PE，`image_seed` 控制 Qwen。主实验每图每个 PE 条件只重写一次，这份文本供两个 image seed 复用。固定 seed 不代替缓存产物与运行环境记录。

### 6.3 PE 输出的接口合同

模型直接回答中的字段是 `rewritten_prompt`；官方脚本导出的记录使用 `positive_prompt`，并提供 `parse_ok`。适配器应显式归一化，不把 JSON、分析文本或其他字段当作实际正向 Prompt。[S1,S3]

检查规则：

1. JSON/schema 有效，重写文本非空且未被截断，`parse_ok=true`。
2. 单图原画布恢复默认应对应 `ratio_follow="<image1>"`、`wh_ratio=""`；明确给出与输入相同比例的 wh_ratio 也可接受。两字段同时非空、错误图像编号或冲突比例记为合同失败。
3. 输出像素尺寸由执行器显式固定。比例相同不等于像素尺寸相同。
4. 官方脚本的 `negative_prompt` 槽默认为空，不得覆盖所有条件共用的执行器负提示。
5. 只做明确的格式解析，不做人工内容修补、额外 LLM JSON 修复或逐图删句。
6. 解析失败、超长截断、画布冲突均记录并计入端到端失败；不得回退 Raw 后标成 PE 成功。
7. 将实际进入 Executor 编码器的文本、有效 token 数和截断标志与 PE 输出对照；排查服务层自动二次改写或默认约束。仅记录 PE 返回文本而没有核对实际消费文本，不算条件链路核验完成。
8. 单图正文按官方规则自然指代输入；多图正文才要求 `<image1>` 等标签。`ratio_follow="<image1>"` 是独立画布字段，不要误当成单图正文也必须含标签。[S2]

主分析同时报告有效输出中的画质效果，以及包含上述失败的端到端可交付率，避免只统计“成功出图”的选择偏差。

本次 1024×1024 实验不验证 3072×4096 或 4K 原尺寸能力。官方规则把明确像素尺寸转换为比例，并将 2K/4K/8K 视作质量词；比例字段不能承担像素合同。高分辨率任务需另记录 request_wh、实际生成/latent 尺寸、pre/post resize 和 saved_wh；最后插值回原尺寸不得宣称原生高分辨率恢复。[S2]

## 7. 执行阶段与预算

### P0：运行合同与历史复用审计

冻结样本、条件、Prompt、权重、代码、参数、ROI、评价标准与历史暴露标签。完成 PE 字段/画布/错误处理的无模型单元测试。

历史输出只有在输入像素、实际 Prompt、模型与 pipeline、scheduler、seed、步数、CFG、负提示、预后处理等关键字段一致且原始输出可取时才可复用。缺字段者标历史参照，不自动并入正式对照。

最多选择两张开发图，对两个历史条件各复跑一个已有 seed，共最多 4 次图像生成，用于复用链路审计。轻微数值差异如实记录；出现影响视觉判断的差异则该层历史数据不复用，补齐对应作业。

**通过标准：**能从记录复原实际执行输入；错误不会被静默吞掉；没有组间隐性参数变化。

### P1：5 张开发图的 PE 审计与成对试跑

每图为 A1、B1 各生成一份 PE 文本，共 10 次主重写；审计文字后运行全部条件和两个生成 seed。

不因重写文本“看起来好”而宣告有效，也不因变长而直接否定。只记录：目标是否遗漏、动作是否弱化、事实是否虚构、夜景是否被改成白天、可靠文字是否被改写、画布是否冲突。

有效但语义不理想的重写仍保留用于评价，不能手动修好后代替原输出。只在技术错误导致协议不可执行时修复接口并重新冻结；所有被替代记录留痕。

**通过标准：**数据链路有效、能完成盲评。不是“必须效果好才准跑后续”。

### P1-I：显式恢复意图 × 官方 PE（新增，必做开发诊断）

**目的：**区分“原始指令没有说清目标”和“PE 未传达已明确的目标”。不修改官方 system prompt，不改模型权重，不重写主实验已有 U0。

仍用 P1 的同 5 张开发图。U0 为原始历史指令。U1 为下列统一、显式的用户指令，所有图使用同一版本，不逐图编造不可观测细节：

```text
Restore this image as a natural photograph, substantially removing visible motion blur, ghosting and noise throughout the image where present. In severely degraded regions, use plausible, scene-consistent reconstruction to recover coherent contours and ordinary textures. Preserve reliably visible identities, object counts, spatial relationships and readable text; do not invent unreadable text. Improve visibility while retaining the original lighting context.
```

U1 的意思是：充分处理整图实际存在的退化，允许严重区域作合理补全，保护可靠内容和原有光照语境。它不要求把每个区域都重绘，也不承诺恢复真实缺失纹理。

语言应与历史 U0 一致。上文是 U0 为英文时的冻结版本；若 U0 为中文，在出图前人工确认并冻结同义中文 U1，在全部开发图复用，不在运行中逐条翻译。该对照同时改变了意图明确度、长度及具体约束，因此只解释为“显式恢复意图包”的干预，不单独声称某句话或纯长度有因果效果。

| 条件 | 用户意图 | 官方 PE | 复用/新增 |
|---|---|---|---|
| A0 | U0 | 无 | 复用主条件 |
| A1 | U0 | 有 | 复用主条件 |
| E0 | U1 | 无 | 新增 |
| E1 | U1 | 有 | 新增 |

E1 每图仅一次 PE（rewrite_seed=42）并缓存，用于 image_seed=0/42；E0 使用相同生成 seed。所有其他参数与主实验一致。新增 5 次 PE、5×2×2=20 张图像。

比较 E0−A0（显式意图直接执行的效果）、E1−A1（PE 路径对意图明确度的敏感性）、E1−E0（明确意图下 PE 的增量）。结合文本审计解读，不直接把差异命名为“PE 保守性”或“Executor 上限”。

这只是开发机制筛查，不能让 E1 取代 A1、B1 的主条件结果，不能把 5 图优势作为采用门槛通过。若 E1 值得推进，下一轮先冻结 U1 与模型配置，再做 C0/E0/E1 的独立验收。主实验工程候选仍在 A1/B1 中预选，避免看见 E1 开发结果后更换本轮主要比较对象。

### P1-R：重写随机性检查

仍用这 5 张开发图；A1、B1 在主 `rewrite_seed=42` 外各增加 43、44 两个重写 seed。所有新增文本都只在固定 `image_seed=0` 下生成。

新增 PE：5×2×2=20 次。新增图像：20 张。

不挑三个重写里最好者回填主结果。观察每图同一路径的可交付率、严重错误、残留退化随改写的波动。如果固定策略反复出现大幅翻转，结论是“单次 PE 不稳定”，而不是通过多抽几次隐藏问题。

### P2：冻结后完成回归矩阵

对其余 20 张完成所有条件和两个 image seed。主重写新增 40 次。已经在开发图上完成的作业不重复。

在看剩余图结果前预选一个工程候选：开发图中，先比较严重错误，再比较可交付率，再比较总体盲评；仍并列时选调用链更简单的 A1。B1 仍作为完整消融保留。

若剩余图不是严格 HELDOUT，本阶段只称冻结后回归，不称独立验证。所有输出保存，不让 Verifier 删除失败图。

### P3：盲评、汇总与决策

完成逐图/逐 seed 评分和预定义配对比较，输出一份 Markdown 报告；选出最多 6 个有代表性的视觉案例，包含失败案例和 `night_0043`。

### 预算汇总

|---|---:|---:|
| 25 图×2 seed 主输出 | 250 | 200 |
| PE 随机性新增输出 | 20 | 20 |
| 显式意图诊断新增输出 | 20 | 20 |

## 8. 评价：先看整图是否可交付，再看局部与指标

### 8.1 人工评价是主判据

建议 2 名独立评审；分歧由第三人裁决。仅能提供一位评审时明确标“单人探索性人评”，不伪称独立共识。

评审看 LQ、匿名候选、预先冻结的问题 ROI 和可信保护事实，不看条件名称、Prompt、IQA 分数。随机化左右顺序；不同条件使用相同显示尺度与裁剪。先看整图，再看原生像素 ROI；不用显示软件的自动增强。

对于每个问题 ROI，恢复完成度 D 使用以下锚点：

| D | 定义 |
|---:|---|
| 0 | 相比输入更差，或出现新的明显问题 |
| 1 | 基本未改善，主要问题仍明显 |
| 2 | 部分改善，但仍影响观看/使用 |
| 3 | 主要问题已明显消除，达到本任务可接受程度 |
| 4 | 恢复充分，残留很轻微 |

自然性 N 采用 0–4：0 明显不合理；1 严重假感；2 有可见不协调；3 基本自然协调；4 自然且无明显人工痕迹。评分不代表缺失细节真实可证。

重要内容错误单独记 `hard_fail` 和原因，不允许高 D 或高 IQA 抵消：可辨身份改变、对象增删、明显错误几何/遮挡、可靠文字改错、无根据地生成重要可读文字、擅自改变画布等。

### 8.2 整图可交付定义

一次生成满足以下条件记 `deliverable=1`，否则为 0：

- 有有效输出，像素尺寸/画布合同满足。
- 无 hard_fail。
- 所有预先标为高优先级的问题 ROI 均达到 D≥3。
- 全图复查没有遗漏的明显严重退化，也没有新引入的明显严重问题。
- N≥3。

若关键内容是否改变无法可靠判断，记 `review_uncertain`，交付门槛先按未通过，并单独报告；普通不可观测微纹理的真实性未知，不自动构成 hard_fail 或 review_uncertain。

辅助输出：高优先级问题解决比例、未解决严重问题数量、最差关键 ROI 得分、内容错误率、自然性。这样可以区分“只修一个局部”与“整图均衡恢复”。

### 8.3 配对胜负

优先比较 A1/A0、B1/B0、B1/A1，以及预选 PE 候选/C0。每对同图、同 image_seed。

先比较交付：一方可交付一方不可交付，则可交付者胜。两方均可交付，再比较整图残留退化、最差关键 ROI 与自然性，实质接近记平。两方均不可交付，主“可交付偏好”记平，另填恢复/风险的诊断性胜负，不把“更好看但仍不可交付”包装成工程成功。

### 8.4 辅助自动指标

复用现有 CLIPIQA、MUSIQ、TOPIQ 和相同实现版本，报告逐图差值与分布，不用它们独立决定优胜。必要时复用固定 ROI 的亮度、饱和、暗部统计，用于定位白昼化/亮部损失，不以越亮越好作为目标。

无 GT 时不将 LQ 当真值计算 PSNR/SSIM/LPIPS 来判断恢复质量，也不把 NB2 输出当真值。已有可靠文字标签才做文字一致性核验；本轮不新建复杂 OCR/身份评价系统。

Verifier 可对固定候选离线打分，检查其与人评是否冲突，但不能参与本轮候选筛除、重试或最终选图。

### 8.5 文本—图像追踪（只记录，不筛除结果）

为每个实际恢复目标保存一行。文本审计者先看原图、source_prompt、final_prompt 并完成标注，再看本轮生成结果，降低事后归因；图像评审继续对条件与 Prompt 盲化。两张表按 target_id 离线合并。

| 字段 | 含义 |
|---|---|
| target_id / region / attribute | 哪个位置的哪个属性需要改变 |
| intent_origin | explicit_user / inferred_from_broad_request / frozen_diagnosis |
| source_evidence | 原始指令原句或输入可见依据，不编造证据 |
| rewrite_coverage | retained / omitted / weakened / strengthened / ambiguous |
| completion_policy | allowed / forbidden / unspecified / contradictory |
| preservation_repaint | none / brief / detailed；附对应句子 |
| unsupported_claim | absent / present；标出新增的无依据事实或具体文字 |
| executor_delivery | 实际消费的文本是否一致、是否截断或再次改写 |
| visual_outcome | 预定义 D、N、重要内容错误、剩余退化 |
| interpretation | 观察到的关联、待检验的解释，不将文本相关性写成机制证明 |

例如：文本明确要求去拖影，实际轮廓仍有拖影，应记录为“该表达与当前配置下，目标未被实现”，不能直接判为“模型能力上限”。若 PE 输出重复描述无须重建的背景且背景发生变化，只构成相关线索；要验证该描述的作用，另做第 12A 节单变量干预。

## 9. 统计与解释

独立分析单元是场景/图像，不是 seed。近重复场景作为同一簇。先图内聚合两个 seed，再跨场景统计；同时保留 seed=0/42 分层结果。

对每个条件报告：有效输出率、整图可交付率、hard_fail 率、不确定率、问题解决比例、自然性、IQA、总时延与峰值显存。总体分母包含计划执行的业务失败；基础设施未完成另报数量，不能悄悄删掉。

配对比较报告 W/T/L 和 `(W+0.5T)/(W+T+L)`，先图内聚合。采用场景簇配对 bootstrap 10,000 次给出 95% 区间；两条件使用同一次重采样索引，不把 50 个 seed 输出当 50 个独立场景。

本轮关键工程比较为“开发阶段预选 PE 候选 vs C0”；A1/A0 和 B1/B0 为机制诊断比较。未经多重比较处理，不把一堆事后最优比较称为统计显著。

DEV、REGRESSION_ONLY、HELDOUT 分开呈现。全 25 图汇总可用于工程回归，但不能覆盖 HELDOUT 结果的含义。样本小、区间跨零时写“趋势/证据不足”，不是“没有任何作用”。

## 10. 预先锁定的工程决策门槛

以下阈值是本项目建议的工程筛选规则，不是论文通用标准；须在看本轮测试结果前冻结。

### 10.1 进入受控集成候选

同时满足：

- 相对 C0，整图可交付率提高至少 10 个百分点。
- 可交付偏好分数至少 0.60。
- 未出现 C0 没有的新严重内容错误案例，且总体 hard_fail 率不高于 C0。
- 生成的两个 seed 分层结果不出现明显方向翻转；PE 重写重复试验未出现同一场景反复严重回退。
- 输出失败、重写耗时和资源成本完整披露；主要收益不只是全图提亮。

这只支持进入受控集成/视觉验收，不自动修改默认配置。

### 10.2 可以提出默认替换建议

除上面的条件外，在至少 20 个真正 HELDOUT 场景上复现，且配对可交付率差的 95% 区间下界大于 0；再完成用户对典型收益与失败案例的视觉验收。

若没有 HELDOUT 数据，即使回归收益很好，也只能提出“值得下一轮验证”。样本内未观察到新错误，不等于真实风险为零。

### 10.3 不采用或暂缓

只超过旧 B0、但不超过 C0：保留现有简洁路径。

恢复增强伴随重要内容错误：不全局采用；整理失败机制，不直接叠加更多负向约束。

仅个别严重退化图有效：作为定向研究候选；后续用独立数据检验触发规则，不用本轮失败集反向定义并宣称路由有效。

结果不稳定或区间很宽：保留多次输出与失败，不以多抽样挑最好者补救结论。

## 11. 结果到架构选择

| 观察 | 下一步方向 |
|---|---|
| A1 > A0 且 A1 ≥ B1、C0 | 优先让官方 PE 做默认指令出口；HarnessIR 暂保留诊断/评价功能，原长 Compose 不必保留 |
| B1 > B0 且 B1 > A1、C0 | HarnessIR 信息有价值，PE 可作为模型原生条件编译器；下一轮研究“结构化目标→PE”，不必长期两次文本改写 |
| B1 > B0，但 A1/C0 更好 | PE 只是在挽救坏输入，不是最优架构；选更简单且质量更好的路径 |
| A1、B1 都无实质收益 | 本配置下 PE 非主突破口；不能据此判定 Qwen 能力已到上限 |
| 更清楚但改错内容 | 当前 PE 输出不满足任务合同；后续聚焦错误对象和动作，不把所有生成一概禁止 |
| 去模糊改善不大，但亮度/IQA提升 | 不宣称达到本项目核心目标；保留区域证据，避免“分数增长掩盖拖影残留” |

若 PE 语义审计通过但图像仍无改善，先检查实际消费的 Prompt、截断、输入缩放与采样条件，再考虑多候选或反馈；语义完整不等于已达到模型最优条件。只有“当前测试的表达/配置未奏效”是直接结论。

本轮结束后才选择下一项干预。不要一次同时修改 Prompt、CFG、局部裁块、Verifier 和生成轮数。P1-I 的 E0/E1 只用于决定是否另立显式意图确认实验，不替换本表主条件。

## 12A. 条件触发的后续研究：不进入本轮默认预算

### 12A.1 未修改内容的详细描述是否导致编辑扩散

**触发：**离线文本审计发现较多 preservation_repaint=detailed，或相关背景漂移线索。

从固定 Prompt 中仅将“未指定修改内容的详细外观描述”替换为一条简短保持声明。保留恢复动作、编辑强度、可信身份/数量/几何/文字等硬要求；不删真正的恢复目标。记为 P-preserve-min，与未改文本在同图同 seed 下比较。文本改动在看相应新输出前确认，不能重写整个 Prompt 后声称只测了保留描述。样本仅按输入/文本筛选时记录筛选规则；按失败图事后选样则明确为探索性研究。

在 5 张符合条件的开发图上使用 2 seed，原始输出可严格复用时新增最多 10 张图。该实验测试“减少非目标重绘式描述”的整体干预，不分离纯 token 长度与语义效应。

### 12A.2 借鉴 PUP 的结果反馈：先检验推理时搜索，不训练

PUP 的官方披露是训练阶段使用生成图像偏好；它不意味着每次推理都会先渲染多张图再改写。下述方案借鉴其“按实际 Executor 输出评价 Prompt”的原则，**不是复现 PUP 的训练方法**。[S7]

待本轮判断明确后，选择一种冻结的起始 Prompt 路径和一份冻结的目标合同，在单独协议中比较：

| 条件 | 3 次图像生成预算内的策略 |
|---|---|
| S0：固定 Prompt 多采样 | 同一 P0，image_seed=101/102/103 |
| S1：无反馈多 Prompt | P0 加两份独立改写，按次对应相同 image_seed=101/102/103；改写不读取生成结果 |
| S2：图像反馈改写 | P0 后，依据前轮实际结果诊断再改写；按次对应同一 seed 序列 |

三组首个候选必须完全相同。三次编辑始终以原始 LQ 为输入，不把上轮生成图当新输入，以免同时测试累积图像编辑。S1/S2 使用同一个改写模型和冻结协议；唯一设计差异是是否提供已生成结果的诊断反馈。不得以不同改写器或另外手写优化提示词替代 S2。

每组使用同一冻结选择器，从自己的三个候选中选一个；最终由独立盲评评价。另报固定候选池的“至少一张可交付”比例、人工回顾的候选池最佳值与选择器 Top-1，前两者是搜索/选择诊断，不能当部署效果。候选内容、Prompt 和失败均保留。

S0→S1 对比多 Prompt 的增量；S1→S2 对比图像反馈的增量。三组 Executor 调用次数相同，不等于端到端算力相同；PE、critic、selector 的调用、时延、GPU 时间都要单列。若需要严格的总算力结论，另做总算力预算曲线，不能只用“每组三张”声称完全公平。

5 张开发图作一次筛查最多 45 次图像调用，共享首候选且完整复用时可减少实际调用。正式验证需冻结后另取独立场景，不能把开发候选池最佳结果当泛化证明。本项不与 P1-R 合并为一次实验，也不把“挑最佳”回填到主实验的单次生成结果。

### 12A.3 FLUX 原生 PUP 独立对照

不是完成 Qwen 本轮验收的前提。确需验证时，仅在 FLUX 自己的 Executor 内比较 Raw/no-PUP 与一次原生 PUP；固定 FLUX 的 checkpoint、system prompt 模式（i2i）、生成配置和种子，检查推理框架没有默认再次 upsample。禁止 PUP 重写后再被内置 PUP 重写一次，也禁止把隐藏启用 PUP 的路径标成 Raw。[S7]

FLUX 官方说明其流程默认使用 PUP，因此 Raw/no-PUP 是组件移除消融，不是默认产品表现。Qwen 与 FLUX 各自使用原生推荐链路做系统对比；不要用不同 pipeline 的原始输出增幅来排名两个重写器的文本能力。PE→FLUX、PUP→Qwen 跨接也不作主优劣证据。

Raw vs PUP 能支持“原生重写组件的整体收益”。要把收益归因于偏好训练，需要同一体系的 SFT-only 与 SFT+preference 权重，并控制数据与训练预算；当前未取得该对照，不能归因。用通用 VLM 替代 PUP 也不能完全隔离这个训练因素。

### 12A.4 多图参考与高分辨率任务

本轮单图 1024×1024 结果不验证多图角色识别、BBox、mask、参考风格迁移或高分辨率。将来迁移参考 Retouch 时需独立核查内容画布与风格参考不互换、来源编号与图像顺序一致；扩展到原尺寸恢复时需独立实施像素合同并记录真实生成分辨率。它们是范围外的必要验收，不是本轮“已考虑即已验证”的能力。
