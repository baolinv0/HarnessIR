# 参考 Retouch：开发实验脱敏摘要

此文仅公开支持工程决策的聚合发现。个人照片、具体文件名、采集信息、案例标识、区域测量与逐图记录保留在所有者本地。

## 验证范围

单个开发案例完成五次主对照：结构化流程两次、直接双图编辑一次、真正无参考的通用增强一次、只有参考派生文字而无参考图一次；另完成一次相同输入与参考的自参考干预。全部六次输出保留，没有挑选后丢弃其他结果。

另有两个不新增生图的原样候选检查，以及零生成的控制器机制检查。图像执行使用宿主工具，其真实后端型号、版本及内部预处理没有公开，因此不能当作已确认 GPT Image 2 或四开源模型的质量比较。结构化流程由 Agent 辅助，没有运行已配置 API 的自动编排。

## 直接支持的工程经验

- 带参考图的条件对部分区域颜色表现出更明显的参考跟随，但结构化流程没有在全部属性上优于通用增强。通用提亮、暖化或 accepted 数量不能证明参考图的因果作用。
- 同一结构化条件的两次调用仍有波动；两次重复和单场景不能证明稳定完整风格迁移。
- 自参考输入已经匹配目标时，直接编辑器仍可能改变外观。系统需要有证据的 already-close 诊断和成功保留原图的路径。
- 外观检查通过的输出仍可能不满足冻结的原生交付条件。对比图放大不能补足原生信息，验收必须分项报告。
- 观察区域受遮挡、材质与不同照明影响；区域有效性需要先确认，证据冲突要复核，不能以数值接近代替真实保真。
- 两个明显的原样候选控制未被误放行，但样本不足以证明验证器的一般可靠性。

## 整合后的机制验证

真实源图与自身组成明确的自参考任务后，生产运行器通过像素一致性证据保留原图，不调用分析 API、编译器或图像模型。该结果验证控制路径，不代表任意参考诊断准确。

重放已保存的候选与冻结评语后，新工作台将外观通过和原生交付不足分开，给出 delivery_not_met；旧案例记录保持不变。重放没有新增图像生成或视觉赞成票。

## 仍需验证

身份可核对的实际后端、不同场景、已知变换目标、困难验收反例和等预算反馈仍需独立实验。当前结果不支持四模型质量排名、任意参考风格的完整学习、精确颜色校准或原有高频细节真实性保证。
