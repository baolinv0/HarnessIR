# GPT Image 2 参考帧 Retouch 全流程设计
日期：2026-10-25。本文保留已批准设计及当时的前置状态。2026-10-26 已进行工程整合，运行实现见 [工作台](../../RETOUCH_WORKBENCH.md) 和 [新运行手册](RUNBOOK.md)；真实宿主输出及其 unknown 后端限制见 [实验结果](CASE_EXPERIMENT.md)。下文“尚未出图/未建源码”等时态描述为原设计记录，不代表当前状态。

## 1. 目标与范围

用户明确：先仅采用 GPT Image 2 完善参考帧风格分析与迁移，覆盖参考帧影响的诊断、提示词、验证及全部相关环节；其他编辑模型在流程稳定后再适配。

本次图像执行器固定 GPT Image 2。诊断、参考理解、提示编译与验证由能看图并输出结构化文本的 VLM/Agent 完成；GPT Image 2 的角色是接受图像和文本并输出编辑图像。分析模型名称由真实部署记录，不能把它标成 GPT Image 2 的文本输出。

A 提供身份、对象、文字、几何、构图与可信细节；B 提供经确认可迁移的摄影外观。当前以同场景、可能未对齐的 A/B 为主要任务。参考失配须显式报告；跨场景参考风格可比性只有在任务明确允许时才评估。图像编码为已声明的 SDR 显示域；相机 RAW/HDR 成像训练、重光照、对象替换与视频不在本轮默认目标中。

成功定义：用户要求的必需参考属性达成，且 A 的保护内容与自然度检查通过。仅“亮度提高”或“更好看”不能替代全部必需目标完成。

## 2. 方案比较与选择

| 方案 | 用法 | 优点 | 代价/限制 |
|---|---|---|---|
| 推荐：显式属性与独立验证 | VLM 分析 A/B→证据→冻结目标→GPT Image 2→独立 A/B/C 验证 | 能定位参考理解、提示遗漏、生成和验证的问题；后续可适配其他编辑器 | 多几次文本分析，需要清楚的目标数据合同 |
| 单次两图长提示 | A+B 直接给 GPT Image 2 | 快、可作为基线 | 内部参考解释不可见，难判断哪些属性遗漏 |
| 专门学习风格变换 | 多场景训练风格编码器/颜色映射 | 可研究复用相机或摄影师 look | 需要数据与训练，超出当前先完善推理流程的范围 |

采用第一种；第二种保留为等生成数对照；第三种暂缓。第一版不增加模型 router、PE/PUP/VGL 分支，也不引入确定性 renderer 作为执行主线。

## 3. 全部阶段的数据流

| 阶段 | 实际获得什么 | 必须输出什么 | 进入下一阶段的条件 |
|---|---|---|---|
| 输入整理 | A/B 原图、brief、编码/方向/几何 | 明确角色、显示域副本、几何记录 | 能确认两图与显示域；不把参考当 GT |
| 诊断 | A/B、用户约束 | 源图诊断、参考外观、区域对应、候选差异、覆盖表、工具请求 | 有支持目标或明确已满足；缺证据进入证据阶段 |
| 证据与复核 | 实际可用测量、独立 ROI、诊断 | 测量记录、可比性更新、冲突与不确定性 | 目标由可用证据支持；工具不可用要显式记录 |
| 目标与提示编译 | 诊断+参考档案+证据+brief | 冻结 TransferContract、完整编辑 prompt | 目标一致、覆盖完整、无未解决的重要冲突 |
| 图像编辑 | 原始 A+B、最终 prompt、声明尺寸/质量 | 原生 C、交付 C、实际调用回执 | 输入角色正确，结果与几何合法 |
| 独立验证 | A+B+C、冻结目标、可信证据 | 逐目标达成、逐保护项检查、伪影和污染 | 所有必需项通过才 accept |
| 有限反馈 | 原始 A+B、上一计划、验证差距、预算 | 目标不变的修订计划或停止理由 | 有具体可支持改法才再次编辑 |
| 报告 | 全过程记录、所有候选、独立人评 | 达成/保真/自然度/成本/失败分别报告 | 不把自动 verifier 作为效果真值 |

中间统计、色板、分割图不默认作为图像编辑附件，避免被当目标内容。必要的局部图只供分析/验证，并保留 A/B 角色和独立坐标。图像编辑的默认附件始终只有 A+B。

## 4. 诊断阶段的具体改造

### 4.1 先分解三个问题

- A 有什么：内容事实、可读/不可读文字、几何、主体与背景关系；技术退化和正常外观分开。
- B 表现什么：摄影色彩/影调/对比；哪些属于场景、材质、光照或视角变化。
- 什么适合迁移：在用户范围内，哪些属性可在不改变 A 内容的前提下迁移，哪些只能保留 unknown。

A 没有噪声/模糊不等于不需要参考调色。source_degradation=[] 不应再自动触发 no_supported_target。只有请求目标已经满足时才走 already_satisfied；参考不合适则记 insufficient_reference，不能伪装成源图已合格。

### 4.2 每次诊断的固定覆盖维度

| 维度 | 核查内容 | 不可直接推出的结论 |
|---|---|---|
| 白平衡/中性色 | 可信中性材质的偏色、混合光分区 | 仅肉眼/显示域均值不能给精确色温 |
| 色相与彩度 | 分色相的颜色强度、肤色/植被/天空等 | 大面积颜色差异不等于应全图匹配 |
| 肤色呈现 | 亮度、渲染色偏、局部对比与高光 | 不改变人物固有肤色/身份，不默认美颜 |
| 阴影/中间调/高光 | 层次、黑白端点、区域明暗、亮部过渡 | 分位数不能唯一确定影调曲线 |
| 局部对比 | 主体立体感、低频明暗与细节可见性 | 不从 B 复制皮肤/织物等纹理 |
| 主体/背景关系 | 分离度、亮度比的视觉关系、色彩协调 | 不移动主体，不改变物理光向 |
| 噪声与纹理观察 | A 可恢复/不可辨细节，B 压缩/裁切 | 不把新生成细节当恢复真值 |

每项均返回 observed / uncertain / not_applicable 与依据。无需每图执行所有目标，但每个请求维度必须说明：形成目标、已经满足、不适用或证据不足。避免长报告没有目标、或短提示悄悄遗漏目标。

### 4.3 区域对应与可比性

区域记录分别包含 A 区域、B 区域、语义/材质、可见范围、遮挡/反光/光向风险。可比性按属性判定：同一对区域可以颜色可比、亮度因照明不同不可比。人工框/多边形或实际分割结果都可以；无工具时可用语义描述与人工确认，不能伪造精确 mask。

状态：comparable / conditional / incomparable / unknown。只有可比属性才能成为强参考目标；conditional 要附允许范围与原因。B 中没有相应内容的区域不得硬匹配到 A 的其他区域。

### 4.4 证据工具

第一版优先复用已有 independent ROI 和 reference_evaluator：Lab 亮度/色度、亮度分位数、彩度与裁切。为中性色、肤色、主体/背景分别测量时明确区域来源。可扩展分色相统计与局部对比描述，但应先验证其解释能力，不把额外指标堆成自动“风格总分”。

视觉判断、工具实测与推断是三个字段，互相冲突时保留冲突。OCR/人脸/结构工具只有实际部署并运行才可报测量；否则独立高清视觉检查或人工评审，必要项看不清时为 uncertain。

## 5. 核心数据合同

新增 reference_retouch_v1，不向旧 v3 的严格 schema 偷加字段。合同内部对象：

| 对象 | 必须信息 |
|---|---|
| SourceDiagnosis | 内容与保护事实、技术问题、外观状态、不可读信息、局部证据 |
| ReferenceAppearanceProfile | 全局/区域属性、observed/uncertain/N/A、证据与参考限制 |
| RegionCorrespondence | A/B 独立区域、语义/材质、属性级可比性和排除理由 |
| AppearanceTarget | target_id、属性、A 状态、B 依据、目标方向、适用区域、mandatory、判据 |
| TransferContract | 目标集合、保护项、排除项、覆盖表、评价规则、版本与冻结状态 |
| EditPlan | 同一目标的执行表达、优先级、当前修正；不定义新评价目标 |
| TargetVerification | 每个 target_id 的 achieved/partial/unmet/uncertain、证据、差距与副作用 |

合同生成后做确定性完整性检查：目标 ID 唯一，必需项有证据与可判定标准；所有要求有覆盖；所有引用存在；没有同一属性“保持完全不变”与“明显改变”的冲突。数字容差只有实际测量与开发校准后才填写，不能让 VLM 编造。

目标不必限制为三条。提示可以归并为少量主操作，但 coverage 必须覆盖全部必需属性。允许的变更通常为亮度、色彩、影调、局部对比；物理光向、身份、对象、几何、文字、可信纹理为保护项。肤色渲染的改变与身份保持分开，不用“保持所有颜色不变”去抵消调色目标。

## 6. 提示词与 GPT Image 2 执行

提示编译按：输入角色→完整目标与优先级→局部关系→内容保护→排除参考特征→输出要求。使用具体观察，不加“高级/电影感/商业大片”等未请求目标。编辑图只输出一张；不给图像模型索要 JSON 诊断或文字报告。

GPT Image 2 执行的 API 边界（2026-10-25 已核对官方文档）：

- 固定 gpt-image-2；正式比较优先固定可用的 gpt-image-2-2026-04-21 快照，不能静默换成 2.5。
- 官方 Images edit 支持文件列表；顺序固定 A 在前、B 在后，n=1，quality=high 为首个质量基线。
- 省略 input_fidelity；GPT Image 2 不能用该参数切换输入保真。
- 不发送未文档化的 seed、CFG、steps。重复请求使用 attempt/repeat 标识，记录实际响应，不能宣称相同 seed 可复现。
- 输入先保持原内容和方向；输出画布以合法尺寸规划，保留 A 比例。若 A 不满足允许尺寸，显式 pad/resize 并记录逆变换，不拉伸、不静默裁切。
- native mask 是软引导；第一版先验证全图外观迁移。以后确需 mask 外像素锁定时使用明确输出融合，同时单独核查边界。
- 原生输出与交付输出分开保存。禁止对 C 自动做回到 A 的颜色对齐，这会抵消参考目标。

每轮始终从原始 A+B 重新生成。新 prompt 表述完整最终目标，并给针对当前问题的修正，不能只写“再暖一点”而丢掉其他目标。

本地技能 check-mode 结果：Garden 未启用且没有配置 API key；宿主存在图像工具，因此技能为 B 模式。宿主工具没有模型选择字段，不能以此确认实际后端为 GPT Image 2。当前未传真实 A/B，也没有出图。

已读 skill 的 scripts/edit.js 只上传一个 cfg.image；正式双图实现须在项目内做正确列表传输，不改安装的 skill，不将 source-only 脚本当两图能力。

## 7. 验证与反馈的完成规则

Verify 只见 A/B/C、独立冻结目标、可信属性证据与几何记录；不见生成模型名称、策略标签和最终编辑 prompt。同一目标 ID 必须逐一返回，不允许遗漏。内容保持、参考接近与自然度分开判断。

| 情况 | 状态与动作 |
|---|---|
| 所有 mandatory 目标 achieved，保护项与重大伪影检查 pass | accept |
| 内容通过，必需外观目标 partial/unmet 且有支持修正 | revise，预算内再生成 |
| 身份/文字/几何重大损伤 | reject；有明确支持改法才尝试修正 |
| 任一必需目标/保护项无法判断 | uncertain；定向检查或人工评审，不自动成功 |
| 生成前确认目标已满足、交付原始 A | already_satisfied，无需强行出图 |
| 预算用完仍未达标 | task_not_met；保留未通过候选或明确 source_fallback |

低优先级改善不能抵消高优先级失败；高 confidence 不能覆盖 unmet；更自然不能覆盖参考未达成。可比 ROI 上的属性距离只是证据，不能替代内容/人评；B 不是对齐 GT，不用全图 A/B PSNR 评价风格。A/C 的内容检查应允许合法颜色变化。

反馈只修改 EditPlan，不修改冻结目标及阈值。若新证据表明原目标不可比较，显式终止并重开合同 revision，不能在当前结果上偷降要求。已达成属性作为新 prompt 的完整目标状态继续保留。无支持改法时停止，避免重复生成碰运气。

默认每案例最多三次图像调用；每次请求一张。诊断一次、可选证据复核一次、初始编译一次、每轮验证一次、两次反馈修订，最多八次文本分析调用。预算可由实际任务明确调整，不采用隐式重试。人工审阅不计作已完成自动验证。

## 8. 与当前 HarnessIR 的集成

经代码定位，现有 v3 仅注册四模型；旧 native_editor 也没有正式 GPT Image 2。原 harness 虽有 GPT2.5 字符串，但走 Gemini generateContent 且只发一张 LQ，不能当成官方两图编辑适配器。

实施采用新的 opt-in 参考 Retouch 路径与新 case，复用 assets/统计/ROI/几何/存储/预算能力。建议最小模块职责为：
- 参考诊断与属性合同：承载本文对象与校验。
- 诊断/证据/提示编译：使用本次提示词包，生成可审阅计划。
- GPT Image 2 双图执行：准确模型、双图顺序、合法参数与实际回执。
- 验证与完成判断：逐必需项和独立冻结评价。
- 控制与报告：衔接已有保存/预算/恢复能力，展示每目标结果。

具体扩展点：stages.py 的阶段 schema/指令；runner._initial_context 的计划上下文；verify 阶段的冻结评价；_accepted 的逐目标完成。旧请求冻结模板与 schema，因此通过新版本显式切换；四个 native adapter 本轮无需改动。

正式落地前需要在工作区建立可运行源码 checkout。当前 review_sources 是审查快照，不直接当成部署工程修改。安装 skill 目录也不作为项目源码。

## 9. 验证计划与验收标准

软件级必要检查：
1. A 无技术退化但与 B 有允许外观差异，仍能进入参考编辑。
2. 参考不合适或颜色受材质/光照混淆，相关属性不能进入强目标。
3. 提示完整覆盖所有必需 target_id，无虚构量化和冲突保护项。
4. 亮度 achieved 但肤色 mandatory unmet 时拒绝 accept；缺失目标/unknown 同样不能成功。
5. 原始 A 已满足时不生成，保存 already_satisfied。
6. 实际双图附件 A/B 顺序正确，input_fidelity/seed/CFG/steps 不发送；次数/回执真实记录。
7. 反馈不改变评价标准，下一轮仍读原始 A+B。
8. 历史 case/template 和旧四模型路径不被新合同静默修改。

真实图像验证：
- 先 4 对开发：全局色偏、肤色、背光高光/阴影、细字/纹理。
- 冻结 12 对不同场景，对比单次 Direct A+B 与完整流程 A+B（24 次生成起步）；不先开展四模型矩阵。
- 少量干预：同一 A 的暖/冷参考、错配 B、已知调色变换。错配 B 应限制/拒绝迁移，不奖励“任何参考都更像”。
- 移除 B 需要区分两种实验：真正 A-only baseline 在诊断、编译、执行、内部验证全链移除 B；共同离线盲评仍按同一参考目标。另一种只从编辑器移除 B、保留由 A/B 得到的固定文本，单独标为视觉条件消融，不能当无参考 baseline。两种只在预先选定小子集开展。
- 独立盲评同时看 A/B/C，对参考达成、内容保持、自然度分别评分。按场景做配对分析，重复调用不充当新场景。
- 只在单轮有证据后比较三次反馈与三次固定提示重复调用的等预算结果。没有 seed 参数，不假装噪声配对。
- 正式通过需真实图像输出和独立观察；模板检查和软件测试只证明合同/调用路径。

## 10. 产物、待确认决策与实施顺序

原阶段提示词包包括 diagnosis、ground-evidence、compose、edit、verify、refine 六个模板。可执行版本现随 `engine/src/hre/retouch/prompts.py` 与 `engine/src/hre/v3/reference_retouch.py` 一同版本化，使用说明见 [运行手册](RUNBOOK.md)。

本轮建议确认的整体设计：显式属性+冻结目标+独立验证；GPT Image 2 唯一图像执行器；A/B 直接入编辑；从原始 A 反馈；先4对开发、12对单模型验证，再适配其他编辑器。

设计确认后先建立运行源码并实现合同/诊断与验证规则，再接双图编辑和报告，最后做真实案例。不得用模板已经写好宣称参考迁移已经有效。
