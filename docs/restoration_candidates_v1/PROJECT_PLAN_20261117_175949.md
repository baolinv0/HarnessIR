# HarnessIR 多候选恢复与证据驱动选图完整方案与实施计划

版本为 1.0，编制日期为 2026-11-17。本文面向工程维护者、离线 GPU 操作者和实验评审者，给出完整方法、实现边界、运行协议、实施验收和实验安排。第 14 章完整收录本轮实验计划正文，可独立阅读，不需要通过链接拼接方案。

代码依据为 `source/candidates/engine/src/hre/candidates/`。批准的原始设计见 [IMPLEMENTATION_PLAN_V1_1.md](IMPLEMENTATION_PLAN_V1_1.md) 与 [CANDIDATE_GENERATION_DETAIL.md](CANDIDATE_GENERATION_DETAIL.md)。运行细节见 [RUNBOOK.md](RUNBOOK.md)。原始规格中的“待实现”是编制时状态，实际状态以本轮验证记录和 [EXPERIMENT_TRACKER.md](EXPERIMENT_TRACKER.md) 为准。

## 1. 背景、目标与交付形态

目前可访问 Codex 的电脑只有 CPU，能够访问外网。GPU 电脑不能访问外网，只能接收源码、依赖和模型文件，并使用能力有限的本地 code agent 调试。工程必须在 CPU 侧尽量完成实现与可复现验证，降低 GPU 侧定位复杂问题的负担。

研究目标是在固定四图预算下增加恢复策略覆盖，同时从候选中交付内容与质量均合格的结果。图像更锐利或相对更好不等于内容已被验证。系统允许最终无法选择，不通过扩大预算、放宽真实性或隐藏失败来产生结果。

工程交付包括独立 candidates 模块、兼容原入口的 CLI、严格请求与几何适配、可恢复操作账本、匿名证据与审核、离线实验统计、测试、源码/wheel、运行手册、完整实验计划和离线 agent 修复说明。模型权重、CUDA 与平台依赖作为独立资产准备。

CPU 验证证明合同和控制流，不证明真实 GPU 兼容性或恢复质量。真实模型 smoke、独立人工/GT 标注和 held-out 统计分别构成后续验收，三者不能互相替代。

## 2. 固定决策与研究范围

新增 `hre candidates` 独立入口，原 `harness/`、`hre/sr/`、reference、v3 行为保持原合同。候选不是原 redo 循环中的多轮，不把四次尝试伪装为重试。

首轮固定 `Qwen/Qwen-Image-2.1` 及其实际 checkpoint revision、Diffusers 来源和全部有效设置。保留原 Diagnosis → Tools → Composition 产生完整 baseline_prompt P0。先从 LQ 生成 C0，观察实际缺陷，再冻结替代策略。所有替代图仍从同一原始 LQ 生成。

四槽代表语义策略覆盖，不是统一弱、中、强档位。不新增第五图，不追跑多轮 Prompt，不引入局部融合、专用人脸/OCR 生成器、硬 mask、PE 优化、跨模型路由或训练。新增这些能力需要独立方案及冻结协议。

默认研究对比是 P0 四次采样的 A 池与反馈规划四槽的 B 池，共享同一 C0。每 case 最多七次 E1 图像调用。J0/J1 为基础审核，J2 是可选消融，不预设专家团一定带来收益。

## 4. 数据对象、身份与冻结

所有新合同使用 `schema_version=hre_candidates_v1`，采用边界验证后的 JSON 字典。对象身份通过规范 JSON SHA-256、文本 UTF-8 SHA-256 和实际文件 SHA-256 分别表达。文本、文件和执行请求不是同一种身份，不能相互替代。

| 对象 | 主要字段或内容 | 必须保持的含义 |
| --- | --- | --- |
| TaskSpec | case_id、source、task_mode、scale、usage_policy、user_intent、rois、critical_attributes | 任务、用途及关键属性在生成前确定 |
| RuntimeConfig | mode、harness_source_root/sha、stages、editor、budgets、review、experiment、seed_schedule、tie_order | 实际参数完整展开；只保存凭据环境变量名 |
| CriticalAttribute | attribute_id、region_selector、attribute、required_for_acceptance、verification_requirement、allow_unverifiable | 指定 visible_consistency 或 verified_content，不能生成后放宽 |
| Issue | 稳定 ID、区域、domain、problem_type、观察、证据、原因假设、替代解释、干预和预期 | 观察与原因假设分开；无充分依据不能编造策略 |
| Requirements IR | P0 source_span、requirement_id、scope、kind、mutable_by、protected_links | 每次替换追溯到原文，保护要求与未解析文本保留 |
| CandidateSpec | candidate_id、slot_id、planned/effective_strategy_id、seed、sample_index、full_prompt、prompt_hash、source_hash、dependency_ids | 槽位、预期策略与实际回退分别保存 |
| Execution manifest | spec、request、editor、prepared、geometry、部署 hash、execution_manifest_sha256 | 文本、模型、seed、输入与尺寸组成唯一实际请求身份 |
| Artifact/receipt | 原生与交付路径/hash、尺寸、状态、来源、几何、Prompt、请求/执行身份 | 完成 JSON 不代表引用的图片仍未改变，必须检查实际字节 |
| Evidence bundle | 匿名整图/ROI、hard_gate、软测量、critical_instances、aliases、pool_hash | 所有证据绑定到源图、候选、ROI、几何与方法 |
| ReviewPlan | variant、必需检查、分包、必需图片、容量、分类及总预算 | 必需覆盖不因容量不足而被删除 |
| SelectionResult | eligible_ids、eligibility_decisions、coverage、best_candidate、best_available_id、selected_output、status | 正式选择属于 eligible，审计上的相对最好不能直接交付 |
| E2 registration/annotations | 预注册 case/seed/目标/slot_axes；实际 axis/strategy/pair_hashes 与人工裁定 | 评价机会由注册目标决定，实际干预不能删减分母 |

F0 在 C0 之前冻结任务、用途、原/规范化/预处理输入身份、模型/部署/参数、seed、预算、审核规则和 E2 注册。F0 的 seal 还必须与 case.json 中原始 f0_hash 相符，不能修改内容后重新计算 seal 来冒充原任务。

F1 在替代生成之前冻结 Issue、ROI、完整 Prompt、依赖、审计结果、回退和请求清单。模型部署清单及源码身份文件在 F0 绑定，生成前重复核对。看到 CF/CT/CFT 后不能回写 F1 或补选评价样本。

研究目标注册与 F1 的实际干预是两份数据。例如注册人物/文字双目标但 Planner 最终只找到一条有依据的干预时，Joint Success 的机会仍保留为非成功。其他轴或 null 也不能使预注册 case 消失。

## 5. 输入规范化与严格几何

只直接接受有解释的 SDR 8-bit 输入。保存原始字节，应用 EXIF 方向规范化，并按可识别 ICC 转为 RGB/sRGB。没有配置解释的 HDR、高位深、透明输入不能静默转换混入研究。不能把原图长边默认缩为 1024。

| 任务 | 预处理 | 原生请求 | 交付与 ROI |
| --- | --- | --- | --- |
| restoration_x1 | 右/下 edge pad 到 32 的整数倍 | 预处理宽高，不改变内容尺度 | 仅裁去 padding，交付 W×H，ROI 按原坐标 |
| sr_x4 | LR 右/下 edge pad 到 8 的整数倍 | native 为预处理 LR 宽高的四倍 | 裁为严格 4W×4H，ROI 坐标按四倍投影 |

257×193 的 x4 示例为 pad264×200、native1056×800、交付1028×772。只允许合同规定的裁剪，不通过 resize 掩盖原生画布错误。保存 canonical_source、prepared_source、geometry 的不同 hash，合法 padding 不要求二者相同。

native 与交付图都保存文件身份和回执。完成记录被复用、case 恢复或报告时，检查实际 native/delivered、匿名整图、ROI 和已有 E2 文件。缺失或不匹配应明确拒绝，不触发一次新的“补图”。

## 6. 从 C0 缺陷到四槽策略

### 6.1 保留原始基线与证据来源

bridge 调用原诊断、工具、视觉打包和 Composition 接口，得到完整 P0。每个外部调用都经过操作账本。工具不可用记录 unavailable，不用空结果推断图中不存在问题。

C0 生成并验证成功后，Planner 读取 LQ、C0、P0、原诊断/工具与预定任务。禁止读取 GT、Oracle、CF/CT/CFT 或离线评分。C0 失败或 unknown 时不执行依赖它的反馈规划，也不换 seed 挑一个更好的基线。

### 6.2 Issue 与干预依据

Issue 必须通过唯一 [Issue schema](schemas/issue.schema.json)。domain 为 person、text、building、grass、other。severity 与任务关键性分开保存。support 为 supported、ambiguous 或 unavailable，可执行性为 plausible、limited 或 unsupported，并记录空间控制风险。

完整字段包含 observation、cause_hypotheses、alternative_explanations、desired_change、protected_attributes、expected_observation、region_ids 和 evidence_refs。模糊只是观察，不能直接证明欠生成或输入已无信息。

仅 supported 且 plausible 的问题进入可执行槽位，优先考虑任务关键性、严重程度与稳定区域/ID 顺序。最多两个有依据的轴。人物蜡感、过度生成和欠恢复可能需要相反策略，不能统一变成“更强”。不可读文字不能靠语义常识补字，更不能将候选 OCR 当 GT。

### 6.3 四槽与自适应规则

| 场景 | 槽位安排 | 约束 |
| --- | --- | --- |
| 人物与文字均有充分依据 | C0、CF=人物替代、CT=文字替代、CFT=同两项联合 | 联合项必须与两单项一致 |
| 单轴有两个不同合理方向 | CF/CT 是该轴 A/B，剩余槽 P0 resample | 实际 axis 标签真实记录，不能仍声称一个是文字/另一个是人物 |
| 单轴仅一个可执行方向 | 该方向占一个槽，其余 P0 resample | 不为凑数编造第二干预 |
| 无充分依据 | P0 四 seed 采样 | 不把随机差异标成有验证的策略改善 |
| 建筑、草地或其他问题 | 按真实 domain 和可执行性分配 | 不假造 F/T，实验适用性仍由注册目标决定 |

slot_id 的固定顺序与 planned/effective strategy 分开。回退保留 sample_index、seed 和预算，真实 candidate_id 按有效策略标记。不能为了获得不同图片而换 seed。

### 6.4 需求 IR、编译与独立审计

先把 P0 需求定位到精确 source_span，区分 restoration_strategy、protection、global 与 other。只替换允许改变的恢复策略。保护身份、表情、已确认字符、布局、背景、颜色和任务要求，保留未解析的原文。

编译器检查 span 无重叠、引用有效、作用域与 mutable_by 一致、保护链接完整。联合替换等于两个单项替换的并集。不能直接追加互相冲突的文字，也不能自由重写整篇 Prompt。

独立 Audit 比较 P0、IR、已编译 Prompt 与 LQ/C0 证据。失败最多做一次批量修复，再审计。区分 compile_invalid 与 intervention_invalid。没有通过不等于可以删除保护要求。

| 最终审核情况 | CF | CT | CFT |
| --- | --- | --- | --- |
| F、T、FT 均通过 | PF | PT | PFT |
| F 失败 | P0 resample | 保留通过的 PT | P0 resample |
| T 失败 | 保留通过的 PF | P0 resample | P0 resample |
| 仅 FT 失败 | PF | PT | P0 resample |
| F、T 均失败或无法安全编译 | P0 resample | P0 resample | P0 resample |

依赖回退是保守约束。不能因为联合项初审看起来不错就越过未通过的单项。单轴 A/B 没有联合依赖时分别判断，失败只回退该槽。

## 7. Evidence 的硬契约与软测量

Code 的淘汰权限只覆盖确定性错误，例如不可解码、错误尺寸、错误来源、Prompt/seed/执行清单不一致、native/交付关系不成立、证据指向其他候选或越界 ROI。所有字段都正确也不等于图像内容真实。

锐度、边缘能量、clipping、LR consistency proxy 和可选 OCR/landmarks/NR-IQA 都是软证据。方法、版本、输入 hash、区域、数值和局限必须明确。未部署为 missing，失败为 failed，不能用 0 代表缺失，也不能据此预删候选。

Evidence 复制匿名 LQ、候选整图和固定 ROI，保留实际传输字节 hash。Judge 只见匿名 alias 与证据引用，不见策略名、seed、Prompt、执行路径或 GT。候选的证据必须同时引用对应源和该候选，不能拿其他图的 ROI 支持当前图。

四槽即使生成精确重复图也保留。记录 delivered 像素 hash、duplicate_of 和每次真实调用。重复率与感知无差异是两种不同指标，不能用统计不显著替代感知盲评。

## 8. 先判资格，再比较最佳

### 8.1 用途政策与逐属性资格

先检查实际硬契约，再检查全部必需区域/属性、恢复充分性和主要伪影。不能从整图一句“总体不错”推断每个关键属性都通过。

| 内容状态 | visible_consistency | verified_content |
| --- | --- | --- |
| supported 且证据完整绑定 | 可进入其他资格检查 | 可进入其他资格检查 |
| no_visible_conflict | 不等于真实性已验证；按冻结政策处理 | 不能满足已验证真实性要求 |
| unverifiable | 仅 photo_restoration 预先允许的属性可保留并披露 | 不合格或未判定，不能声称正确 |
| conflict | 根据有效证据拒绝，重大内容冲突不得被总分覆盖 | 同样拒绝 |
| missing 或 coverage 不完整 | 必需项为 undetermined | 同样为 undetermined |

information_critical 的关键身份与文字要求 verified_content，不允许用自然度、OCR 高置信或语言合理性替代。photo_restoration 的 allow_unverifiable 也必须在生成前设定，不能看到结果后放宽。

### 8.2 ReviewPlan 与 J0/J1/J2

ReviewPlan 在调用前声明全部必需检查、每包图像、每候选覆盖、聚合与预算。重要 ROI 超过单包能力时分包，终审同样受容量和预算约束。放不下则 unresolved，不静默截断 ROI。

J0 使用图像，J1 增加绑定软证据。J2 的 J-P 关注人物与表情，J-T 关注文字与笔画，J-G 关注背景和技术损坏，J-U 关注正常观看，终审核对证据和完整资格。不能对专家分数求均值替代证据裁决。终审否决或缺评参与资格，不只影响排序。

每项最多一次格式修复，必要时一次顺序置换复核，均是新 operation 并占分类和总预算。unknown 不是一次免费格式修复。多视角利益只能在同池、预算与模型条件披露后讨论。

### 8.3 正式选择与未解决结果

先形成 eligible_ids，只有资格完整且未被拒绝的候选进入 Listwise 排序。并列时优先 C0，再按冻结槽序决定，不能用临时主观选择替代。

best_candidate 必须属于 eligible。没有 eligible 时，正式输出为空，状态 unresolved。best_available_id 可供审计，但不交付为已确认合格结果。J1 选择保存在正式 selection，其他 variant 独立存档，不覆写主结果来制造比较。

## 9. 操作账本、状态机与成本

runtime 是 case 级变更入口，复用 case_lock 与原子 JSON 写入。持久化对象是可读快照，操作账本是外部请求与预算的单一权威，不另建 SQLite 或第二份费用状态。

正常主通路为 created → baseline_ready → plan_frozen → candidates_complete → evidence_ready → selected/baseline_retained/unresolved。blocked、failed、unknown 和 judge_failed 分别记录原因。candidates_complete 表示预定槽已终态化或有明确缺失，不承诺四图都成功。

每个 operation_id 包含实验分区、阶段/variant、包、候选和 attempt 身份，并绑定完整请求 hash。Composer 的第二次调用、重写修复、独立审计和 Judge 修复分别记账。不能用 SDK 隐式重试绕过日志与预算。

| 操作状态 | 恢复行为 | 预算规则 |
| --- | --- | --- |
| prepared | 校验保存的请求后按合同提交 | 已保留类别及总额度 |
| submitted 但无可靠终态 | 转 unknown，不重发 | 额度与费用不确定性保留 |
| completed | 校验回执/响应/实际文件后重放 | 不新增调用、不改 seed |
| failed | 重放原失败，保留终态 | 不将失败当作免费重试 |
| unknown | 只允许对账或保持未知 | 不自动退额度、不重新调用 |

对账 decision 为 confirmed_completed、confirmed_not_executed 或 still_unknown。证据必须绑定 operation_id 与 request_sha256，图像操作还绑定执行清单。confirmed_completed 需要可核查 response/receipt；confirmed_not_executed 需要提供商/worker 的未执行证明。PNG 或文件时间不能证明实际费用。

已确认未执行仍保留原图像调用额度，默认不补图。相同 resolution hash 再导入为幂等操作。A 池有独立账本与 reconciliation 目录，恢复不能使两池已完成调用重新执行。

### 14.2. 研究问题、声明与反证

问题是固定四图预算下，单一恢复 Prompt 的重复采样能否覆盖人物与文字的不同恢复需求，以及审核器能否选择真实合格的图，而不是选择锐利但内容错误的图。

| 声明 | 最低必要证据 | 对应实验 | 不足以支持声明的结果 |
| --- | --- | --- | --- |
| C1，主要声明。反馈规划的候选池比同预算 P0 重采样更容易包含可用答案，并改善最终系统输出 | Held-out 的 A/B 配对 Oracle Pass@4、Selected Pass、内容错误与成本。另以预注册同 seed E2 检查策略方向 | B1、B2、B4、B5 | 只展示几个好例子，或只看锐度，或删掉失败 case |
| C2，支持声明。软证据帮助审核，同时不放宽内容资格 | 同一 B 池、相同匿名次序与模型下 J0/J1 比较，报告选对、误拒、误纳及 unresolved | B3、B5 | 同时改变生成模型、候选图片、政策或预算后归因于软证据 |

必须排除的解释是增益只来自更多生成次数、不同 seed、额外 Judge 调用或挑选成功 case。A/B 每池都是四槽。共享 C0 后每 case 最多七次 E1 图像调用。E2 使用另外两枚相同评价 seed 做配对，不能把 E1 的不同 seed 差异解释为 Prompt 因果作用。

本轮固定一个图像模型及部署版本，不声称 Qwen 优于其他图像模型，也不声称结论跨所有 backbone 泛化。不新增模型训练、长基线清单或昂贵模型搜索。删除性比较由 C0 单图、A 池重采样、J0 与 J1 承担。

### 14.5. 预注册、seed 与算法身份

E1 seed schedule 固定为 `[0,1,2,3]`。E2 评价 seed 固定为 `[10001,10002]`，不得与 E1 重合。抽样 seed 为 20261117。

E2 名单在阅读 E1、C0、Judge 和 Oracle 结果之前生成。按 LQ 主类和信息量、尺寸子层抽样。当前 `study.py` 的实际算法名为 `seeded_strata_round_robin_sha256_v1`，先按类 seed 打乱子层顺序，子层内按抽样 seed、case_id 的 SHA-256 排序，再轮转取样。类内不足则取全部并记录 shortfall，不跨类借额，不补入成功 case。

`examples/experiment_protocol.default.json` 是待实例化模板。其旧 `selection_algorithm` 标签与当前输出算法名不同。G1 冻结前必须在实际协议中记录上述实现名称及子层顺序规则，核对 preregister 输出的 `strata`、`shortfalls`、算法名和 hash。不能只改标签后继续声称使用旧的纯字节序子层顺序。

预注册输出包含 case_ids、cases、evaluation_seeds、dataset/protocol hash 及 freeze_hash。保存输入数据清单和协议的原始字节。对 E2 选中 case，在创建 F0 时设置 `experiment.e2_manifest_path`，不能生成后补接。

Pilot 结束后最多修订一次协议。记录修改原因与内容，再冻结 held-out 的名单、配置、代码和分析脚本。持有 held-out 标签的人不得用其结果选择协议或模型。

### 14.6. 五个实验块

#### B1，基础能力与公平基线，必须运行

问题是原始四槽生成与内容资格在真实模型上是否成立。先用独立工程图执行 restoration_x1，再用 257×193 的真实 LQ 执行 sr_x4。两者使用独立新 case，不计入 Pilot。

验证请求中的 Prompt、seed、canonical/prepared LQ hash、部署 hash 和回执。x4 的 LQ pad 为 264×200，请求 native 为 1056×800，精确裁剪为 1028×772。不能通过 resize 修正原生尺寸错误。x1 按 32 网格准备，并裁回原内容尺寸。

成功条件是环境预检通过、原生和交付几何正确、没有隐式下载、正常 resume 不新增调用，修改已选图片后被拒绝。失败说明当前运行环境或适配链路尚不能承载后续研究，不说明方法质量好坏。目标产物为环境记录和一张几何/回执核对表。

#### B2，A/B 系统主实验，必须运行

在 Pilot 10 张和冻结的 held-out 24 张上分别生成 A/B。每池四槽，两池同用 J1。人工对七张唯一图独立标注，同一共享 C0 的质量标签复用，但两池最佳集合分别标注。

主指标为 Selected Pass。Oracle Pass@4 判断生成池是否出现好答案。辅以内容错误、ContractValid coverage、误拒/误纳、unresolved 和成本。保存 B−A 配对差值、胜平负和 case bootstrap 区间。

支持 C1 需要 held-out 改善方向与内容安全、失败率和成本一起成立。置信区间跨 0 时报告不确定，不宣布稳定提升。若 Oracle 改善而 Selected Pass 没改善，问题更可能在审核而非生成；若只有 selected 改善，不单凭此断言候选覆盖增加。目标表为 A/B 主结果与全部失败分母。

#### B3，固定池 J0/J1 审核比较，必须运行

复用同一 B 池，不新增图像调用。执行 J0，与默认 J1 比较。检查 pool_hash、候选次序、ROI、用途政策、模型和采样配置一致。J0/J1 的差异只能是预先约定的软证据输入。

记录 Selected Pass、Conditional Selection Success、Best-in-pool Agreement、False Reject、False Accept、eligible 误纳、缺评和费用。未解决缺包或关键内容未知时允许 unresolved，不能强行选图。

现有批量主入口固定读取 J1，J0/J2 的比较必须从各自 `judge/<variant>/selection.json` 建立独立离线表，并与同一 Oracle 标签关联。不能覆盖 `selection.json` 来让主汇总假装支持其他 Judge。

若 J1 未改善选图或只增加成本，C2 不获支持。若 J0 已足够好，不把更复杂 J1 作为默认必胜方案。目标表为固定池审核比较与误拒/误纳归因。

#### B4，预注册 E2 同 seed 策略分析，必须运行

在预先抽出的 Pilot 4 张、held-out 8 张上，以两枚新 seed 分别执行冻结的四槽 Prompt，每 case 额外八次图像调用。F1 从原 E1 C0 冻结，不重新规划，不根据 E2 修改 Prompt。

每个实际替代槽与同 seed P0 图配对。统计 Target Improvement、Off-target Regression、Joint Success、Joint Compatibility 及覆盖。每个槽、预注册评价轴分别报告，不能事后取 A/B 中效果最好者。

注册分母保留 C0 失败、fallback、错轴、无有效干预、执行失败和缺评。Joint Compatibility 只解释两单项本已成功且无回退的完整配对，不得用机制 not_applicable 删除端到端 Joint Success 的失败。

支持机制需要有证据的目标改善，同时没有重要非目标退化。单纯更锐利、像素变化或不同 seed 的好看输出不算机制证据。目标产物为策略效果表、同坐标 ROI 图和原始裁定记录。

#### B5，内容风险、简化与失败诊断，必须运行

从全部预定 case 报告失败类型，不只选成功示例。固定反例至少覆盖清晰错字、自然但换表情、人物改善而背景严重欠修、草地改善而人物受损、低锐但自然图。若真实数据缺少某类反例，单独列出补充诊断集，不能伪称它属于预注册主样本。

按任务政策分层报告错字、身份/表情/姿态冲突、结构损坏和严重背景伪影。比较内部基线 C0、A 池、B 池及 J0/J1，判断新增规划和证据成本是否值得保留。

成功条件是失败、未知和缺评可追溯，简化的对照能解释必要复杂度。负结果应直接约束声明，不能靠增加组件掩盖。目标产物为失败分类表与正常观看、ROI、GT 三阶段的案例说明。

### 14.7. 可选实验及实施边界

J2 只在 Pilot 出现明确选图失败且有改善空间时启动。复用固定 B 池，默认每池每 variant 最多七次调用。若 J2 不改善选择且提高成本，保留默认 J1。未运行时写 J2=not_run，不阻止检验生成假设。

若要把 J2 收益归因于专家分工，需要 `J1_budget_matched`，匹配模型、证据、必需检查、primary/aggregate/repair/dispute 上限及输出 token 额度。当前公开 CLI 没有该 variant，须先完成独立实现和验收，再增加协议版本。本计划不提供虚构命令。未做时只报告多角色、多预算系统效果。

`J_soft_gate`、模型更换、更多候选、其他 backbone 和新策略搜索均为可选扩展。不得用未预注册阈值删除候选，不占用本轮主实验声明。SSIM、LPIPS、CER 和身份模型指标只在离线侧补充，工具未部署时明确 missing，不能填 0 或进入在线 Judge。

### 14.11. 独立标注协议

两名评审互不读取在线 Judge、策略名称、Prompt 或另一评审结论。先以匿名随机次序看正常尺寸整图，记录自然度和可用性，再看固定坐标 ROI，最后在独立内容检查中查看 GT。两阶段记录分别保存，不能把“更好看”直接当作真实性通过。

E1 每张图记录合格与否、已确认内容错误、适用属性、证据引用和评审身份。最佳集合必须位于实际硬契约有效且人工质量合格的集合中。最佳标注与硬契约冲突时复核或记缺失，不把失效最佳图直接过滤后算一次选错。该行为已通过 G0 的单案例与批量回归验收。

E2 先匿名随机左右比较同 seed 替代图和 P0。每个注册 ROI/属性记录 improved、tied、worse 或 undetermined，以及 material_damage、content_conflict、overall_acceptable、图像 hash、证据与理由。两人分歧交第三人裁定，无裁定为 undetermined。只有一人时明确 single_rater。

原始表保留 rater_id、adjudication、左右顺序、可见性和理由。裁定后转换为当前 `analysis.py` 文档定义的 annotation JSON。转换记录将匿名 pair 关联到实际 slot、axis、effective_strategy_id 和 pair_hashes，不丢弃原始表。

原始 GT、Oracle、效果标注和未匿名对照只在离线侧可读。在线配置和请求日志必须审计，确认没有这些真值路径、标签或文字答案。

### 14.12. 统计合同与结果解释

令 U 为实际硬契约通过集合，A 为 U 中独立 Oracle 确认合格的集合，B 为 A 中独立并列最佳集合，S 为在线正式选择。软证据不决定 U。

| 指标 | 规则 | 失败和未知 |
| --- | --- | --- |
| Produced / ContractValid coverage | 已产出/实际硬通过槽数除以全部预定槽数 | 所有预定 case 保留；失败不删除 |
| Oracle Pass@4 | A 非空的 case 比例 | 不完整 Oracle 披露 missing；未确认者不能算合格 |
| Selected Pass | S 属于 A 的 case 比例 | 无选择、失败或不完整 Oracle 保守记非成功 |
| Conditional Selection Success | A 非空时正式选对比例 | 不能用无答案 case 稀释条件分母 |
| Best-in-pool Agreement | A 非空且有效最佳标注完整时 S 属于 B 的比例 | 冲突或缺失最佳标注单独计缺失。G0 通过后才作为正式结果 |
| False Reject / False Accept | 对实际 A 与 eligible/正式交付计算 | 只在 Oracle 完整 case 计算，同时披露全体数和完整数 |
| Target Improvement | 槽的全部预定目标均改善且无新增目标内容错误 | 分母是预注册适用 case × 两 seeds。回退、失败、缺评不成功 |
| Off-target Regression | 至少一个重要非目标 ROI 有实质损害 | 分母只用预定且完整配对评审，另报全部预定、失败、缺失数 |
| Joint Success | 全部双目标改善，整体合格且无重要非目标损害 | 保留全部注册双目标机会，不能按 F1 删减 |
| Joint Compatibility | 两单项已成功时，联合保留二者的比例 | 仅完整、无回退机制子集。其他为 not_applicable 并披露占比 |
| Exact Duplicate Rate | 至少两图 case 中像素 hash 唯一数少于成功槽数的比例 | 额外报告不足两图数，不删重复槽或成本 |
| Perceptual Diversity Collapse | 完整盲评或裁定认为成功槽无可辨差异的比例 | 缺评单列，统计不显著不等于感知坍塌 |

全部比例保存 numerator、denominator 和 missing_count。零分母为 null，并说明不适用。A/B 使用按 case 重采样的配对 bootstrap，10000 次、seed=20261117，报告 B−A 差值的 2.5%/97.5% 分位数及胜平负。不能把同一 case 的候选、ROI、两枚 seed 当独立样本。

当前汇总 CLI 自动输出 E1 Oracle/选择配对统计与 E2 人物/文字注册槽指标。内容错误分型、精确重复率、感知坍塌、完整硬件成本和 J0/J2 对比需要依据原始记录在独立离线表中计算并复核，不得因没有专用汇总命令而省略。可选 GT 指标只作补充，不单凭 PSNR 选择在线输出。

Pilot 结果只用于诊断。Held-out 仍是小样本，报告区间和局限。没有稳定证据时结论为未获支持或不确定，不预设提升百分点，不把小样本负结果包装成已证明等效。

### 14.14. 失败、恢复和离线 agent 修复边界

blocked 先检查依赖、真实路径、checkpoint 身份、端点和容量，不改方法绕过。unknown 表示调用可能已执行，消耗已保留预算，不自动重发。失败、重复图和 unresolved 都留在预定分母与成本记录里。

有确认回执或未执行证明时，按 RUNBOOK 将绑定证据放入 case/reconciliation。A 池使用 case/pools/A/reconciliation 并传入 `--pool A`。reconcile 本身不生成图，之后 resume 只重放完成调用。仅有一张 PNG 不构成完成或费用证明。

output_modified、freeze_modified 或 selection_binding_mismatch 必须保留现场，查明来源。只有精确恢复原字节才能继续原记录。不能删账本、重置 seed、伪造回执或把真实运行切换为 fixture。原生尺寸错误不能靠 resize 修补。

离线 code agent 的修复记录至少含错误码、复现命令、环境版本、最小 diff、回归结果、实际模型 smoke、受影响 case 与全部未知费用。改变在线生成、选择或协议的修复必须决定是否使已生成结果失效。Held-out 中途若必须改变算法，停止该轮，报告已消耗样本，不能在同一封存划分上调完继续声称独立测试。
