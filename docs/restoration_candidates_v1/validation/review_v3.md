## P2 / 原始最佳图被硬契约排除后，仍计算一个虚假的最佳选择失败

位置为 `engine/src/hre/candidates/analysis.py:131`、`:138`，以及 `engine/src/hre/candidates/report.py:136`、`:145`。

修复后的代码先将独立最佳集合与实际合格集合相交。当原始人工最佳图不满足硬契约时，该交集可能变为空集。两条报告路径仍根据“传入了最佳字段”把此 case 计入最佳一致率分母，且 missing_count 为 0。

实际复现中，人工质量合格集合有两张图。原始人工最佳图未通过硬契约；另一张图是唯一同时满足硬契约与人工质量合格的候选，而且系统已选择它。单案例和批量结果均为：

| 指标 | 实际结果 |
| --- | --- |
| 实际硬契约与 Oracle 均合格的候选数 | 1，等于正式选中图 |
| Selected Pass | 1/1 |
| Best-in-pool Agreement | 0/1 |
| Best-in-pool missing_count | 0 |

唯一合格图必然是有效集合内的最佳。此时不能把已失效的原始最佳标注当作一个已知的选择失败。这会低估最佳一致率，并影响 A/B 的统计比较。应拒绝与有效集合冲突的最佳标注，或将该指标标注为缺失并排除对应分母；不能由质量最佳图被过滤而直接得到一个确定的 0。

独立代理使用公开 fixture、实际生成文件和两条离线 API 复现，脚本为 `.work/review-v3-statistics/repro.py`，结果为 `.work/review-v3-statistics/proof.json`。父代理另用单元素实际合格集合独立确认，证据为 `artifacts/review-v3/best-valid-singleton.json`。现有回归测试只覆盖了过滤后没有任何合格候选的情况，没有覆盖“另有合格候选且已选中”。

## 范围和判断边界

按 Prove It Works 原则，本轮使用实际文件、CPU 复现和实际安装后的 CLI。代理分别只读审查运行时、统计和注释约束，父代理负责打包身份并复现统计反例。使用当前可用模型，不是跨供应商复审。

非标准单轴多槽仍需要 E1 前显式冻结 slot_axes，这是已说明的设计约束，不作为新缺陷。真实 GPU 推理、Diffusers 画布能力、显存及模型效果未验证。本 P2 影响离线 Best-in-pool 指标；在复现中生成、正式选择和恢复逻辑均正确。

建议先关闭该统计问题，再冻结最终实验统计报告。当前 CPU 工程检查可以支持继续准备 GPU 联调，但不能把测试通过解释为所有离线统计已完全正确。
