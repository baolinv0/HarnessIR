# 第二轮复审修复

本轮修复离线交付前复审发现的 R1 至 R4。源码、wheel 和 ZIP 必须来自同一修复后快照。原始复审与复现保留在开发工作区 `artifacts/review-v2/REVIEW.md`。

## 统计身份

预注册评价目标与实际干预分开记录。E2 的注册槽映射和 LQ 目标决定哪些 case/seed 比较进入分母。F1 的实际轴、无干预、回退或缺失结果不能缩减这个分母。非标准单轴多槽实验需要在 E1 前的 `slot_axes` 明确各槽的评价轴。

实际 building、grass、other 产物可以完成汇总。报告保留其实际轴和产物覆盖。人物/文字指标按预注册目标判断适用性，不虚构其他场景的质量公式。

Oracle 质量标签与 Evidence 硬契约集合分别保存。只有两者都通过的候选属于正式合格集合。硬契约失败或未知不能被人工字段覆盖。单案例评估和 A/B 汇总采用同一个硬契约集合函数。

## 文件身份

复用已完成候选之前，验证实际 native/delivered 文件与记录及回执中的 SHA-256。公开 run/resume/judge/report/e2 操作也检查匿名整图、ROI 和已有 E2 输出。正式交付路径必须属于已审核选择。

发现完整性错误时拒绝操作。保留原完成记录，不能转成普通生成失败后覆盖它，不能重新提交该模型调用。恢复精确原文件后可以继续检查；改变研究输入则应创建新 case。

## 验证记录

新增回归测试先复现缺陷，再验证修复。原始输出完整性回归有 10 项 RED；修复及中断恢复检查共 11 项通过。统计、Oracle 和 Evidence 的定向验证共 38 项通过。完整候选测试为 133 项通过、1 项因 Windows 符号链接权限跳过。统计回归的 RED/GREEN 和最终测试结果写入 `validation/cpu_results.json`。安装后 CLI 故意修改已选匿名副本，已确认恢复拒绝且操作账本不增加调用。

按 Model the Domain 原则，将注册评价与观测干预建模为独立数据。按 Prove It Works 原则，最终验证使用实际安装的 wheel 和实际解压的交付包。完整性检查增加本地文件读取，不使用额外模型调用。

CPU fixture、模型边界替身和真实 GPU 运行分别记录。真实 GPU 推理、显存、Diffusers 画布能力及研究效果仍需在目标机器验收。独立复核使用当前可用模型，没有跨供应商审查结论。
