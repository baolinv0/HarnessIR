# 数据与补充信息

**目标**：让四模型看到完全一致的 A/B，并让实验结论确实回答前置成像的需要。以下尚未由用户确认的内容不能当成事实填入报告。

## 一、启动正式实验前必须明确

| 项目 | 请提供的最小内容 | 为什么需要 |
|---|---|---|
| 配对数量 | 是 20 对，还是两机合计 20 张？每个 `pair_id` 对应哪个 A 和 B？ | 决定样本数、运行量和分母 |
| 实际输入 | prediction A 和 iPhone B 的服务器路径表；最好先给 2–3 对未经聊天软件压缩的文件 | 验证配对、可读性、方向、镜像、裁切和颜色 |
| prediction 的数值含义 | 文件格式、dtype/位深、数值范围、RGB/BGR、色域/primaries、白点、transfer；是否已做 WB/CCM、tone mapping、gamma | `linear` 只说明传递关系的一部分，不能自动等于 linear sRGB；也不能给已编码 sRGB 再加 gamma |
| baseline 冻结身份 | 代码/模型版本或可追溯 ID、权重 hash、预处理与导出脚本版本；这批人物/场景是否参与训练或调参 | 保证输入一致；区分开发集表现与未见数据验证 |
| iPhone 输出定义 | 具体机型和拍摄模式，JPEG/PNG/HEIC，ICC 色域，SDR/HDR/gain map，导出方式；是否有美颜/人像处理 | B 必须有明确显示意义，不能把 P3/HDR 文件直接当未知 sRGB |
| 任务目标与保护项 | 希望接近 B 的曝光/肤色/白平衡/对比/高光/局部影调优先级；是否同时要求降噪/去模糊 | 避免把“更锐”“更白”误当目标；默认不改脸型、五官、表情，不自动磨皮美白 |
| 测试尺寸 | A/B 原尺寸、计划输入尺寸、最终是否要求原尺寸交付；统一缩放规则 | 约 1MP 与原始多 MP 不是同一个画质问题；pad32 不会降低原图推理负担 |
| 场景分组 | 独立场景/拍摄 session/连拍组 `group_id`、人物匿名 `subject_id`、重复图/裁块关系 | 防止重复场景跨开发/正式；seed、ROI 和评分人数不增加独立样本数 |

如果 A 已是明确导出的标准 sRGB SDR PNG，可以直接提供该文件及导出说明，**不必为运行编辑模型重新上传全部 linear 原始数据或 baseline 权重**。保留原始数据路径/hash 即可追溯；需要检查 baseline 本身时再读取。

## 二、建议补充，可先采用保守默认

| 项目 | 建议默认 / 可提供信息 |
|---|---|
| 额外开发数据 | 另给 2–4 对用于安装排错与冻结设置；没有时按计划处理数据划分 |
| 拍摄差异 | 两机是否同一人物/近似同时拍摄、表情/姿态/光照是否变化；前置镜像、焦距/FOV、旋转、裁切是否不同 |
| 场景标签 | 室外/室内/低光/逆光/混合光、是否多人、是否眼镜/头发细丝/文字；按实际存在记录，不补造配额 |
| ROI | A/B 各自的脸部或皮肤、头发、衣物、背景 ROI，坐标独立；默认先 full frame，ROI 用作分析证据 |
| 服务器 | GPU 型号、张数、单卡显存、驱动/CUDA、可用时间，已部署权重和本地 VLM 完整 ID/revision；不用提供密码/token |
| 人评 | 推荐 3 名评审、相同 SDR 显示条件；若只有 1 人，报告为单评审案例分析 |
| 输出取舍 | 默认保真是硬门，外观更接近 B 是改善目标；无法从 A 验证的微小细节不得称真实恢复 |

## 三、颜色出口：必须在所有模型前只定义一次

1. 保留原始 S26 linear、baseline 原始 prediction、iPhone 原文件及 hash。
2. 明确 prediction 是否仍为 camera-linear RGB、linear sRGB、log、或已经显示编码。若为未知 camera RGB，仅套 sRGB gamma 或 ICC 标签不足以完成相机显色处理。
3. 由冻结脚本完成所需色域转换、白点适配、tone mapping/SDR 渲染、传递编码和量化。若本来就是 sRGB SDR，则不得重复 gamma / tone map。
4. iPhone 单独按正确 ICC 和 HDR/SDR 定义导出。不能为让指标变好，在每个输出后做单独曝光补偿、直方图匹配或对参考的颜色拟合。
5. 对 A/B 统一明确尺寸规则、方向与前置镜像政策。不得按 iPhone 几何变形 A；B 的 ROI 坐标独立标注。
6. 最终保存可复现的 opaque、8-bit sRGB SDR PNG（建议包含正确 ICC），记录输入输出 hash、裁切/缩放、clipping 和转换脚本版本。目录生成器只校验声明与文件 hash，**不会验证这些像素是否真的符合声明**。

现有 `hre_task_v3` 会做 EXIF 方向归一化和有 ICC 的 sRGB 转换，但不实现 RAW 显影、HDR tone mapping 或任意 linear→display 转换。对于已明确导出的 sRGB 无 ICC PNG，可以显式 `assume_srgb`；“未知颜色”不能用该选项消除。
