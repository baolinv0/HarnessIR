第一阶段工程规格

1. 目标与已确定的设计

用户要在 Windows 笔记本上，通过 ChatGPT 的诊断、提示词编写、图像编辑、验证能力和离线视觉工具，连续完成单图恢复。用户不再重复说明各阶段上下文；系统显示下一动作、所需文件和当前完整任务。

采用 Python 本地控制器 + 共享文件夹 + Streamlit 向导 + ChatGPT 角色会话。已有讨论已确定文件交接与 ChatGPT Executor；本轮将它固化为工程规范。控制器不调用外部模型 API，不抓取 ChatGPT 历史，不安装或调用 cline，不自动登录或修复认证。外部模型在用户选定的 ChatGPT 会话中工作。

本地工具可以使用预先配置的本机模型服务或固定离线命令，第一阶段接入按需本地工具进程与缓存，手动文件导入作为降级；详情见 docs/10。用户的其他 Naive/ARIS 本机调用约束不被本方案改变。控制器、图像编辑器与联网 ChatGPT 的职责不能混同。

2. 范围与成功标准

P0：创建 case；绑定不可变输入；发出 diagnoser 任务；接收严格 JSON；按诊断中的工具计划等待证据；发出 composer 任务并接收实际模型生成的 instruction；执行图像编辑；校验输出；独立 verifier 判定；必要时 refine；终止并导出审计报告。自动部分包括任务生成、缺失项检查、文件接收、状态迁移与报告。

自动启动外部会话、自动保存图片、自动跑工具是独立能力，需要本机探测通过才启用。不能把“用户保存了图片”记为“系统自动生成并写盘”。第一阶段不承诺跨回合永久后台无人值守。

完成条件分开记录：workflow_completed 表示闭环已终止；restoration_success 表示选定图像被 verifier 判为正确且图像约束通过。工程验收通过不代表算法有增益。

4. 用户可见交互

首页列出 case / 状态 / 阻塞原因。详情页只突出一个“下一步”：需要上传什么，在哪个已指定角色会话执行，是否可自动回写。含原图、当前 Prompt 复制、任务目录打开、JSON 导入、结果图上传、工具缺失清单和历史。

按钮：新建、复制当前任务、导入 JSON、登记工具证据、提交编辑结果、暂停、继续、导出。停止时用户可取消 case，但不能人工把失败改为成功。人工改 Prompt 必须复制为 manual_variant 新分支，完整记录父 case，不能混入预注册 benchmark 主组。

5. 文件布局

目标根目录下：Data/ 为已有数据；Design_v1_20261012/ 为本包；cases/<case_id>/ 存单图；runtime/capabilities.json 存本机探测；logs/ 存操作日志。所有 case 内路径使用 / 分隔的相对路径，控制器用 pathlib 映射 Windows 路径。

每 case：input/original.*、input/canonical.png、case_config.json、state.json、events.jsonl、transactions/、tasks/<task_id>/request.json 与 prompt.txt、tools/<tool_id>/、rounds/round_001/、final/、quarantine/。

Canonical 是统一用于所有角色与两组编辑器的、仅做 EXIF 方向 / 已知色彩空间处理的照片；与 original bytes 都保留。禁止按组分别缩放或调亮。工具也对 canonical 运行。研究中的“从原图重试”指该固定 canonical，而不是上轮生成图。

6. 默认配置与限制

  • Python 3.11+，Streamlit、Pydantic 2、Jinja2、jsonschema、Pillow、filelock；watchdog 可选，默认每 1 秒扫描 done 标记。
  • 一进程一根目录写锁；多 case 管理，外部 ChatGPT 队列默认一次只派发一个任务。
  • 主 profile：chatgpt_adapted_v1；模板 / 配置 / intent 创建 case 时锁定。
  • 默认每 case 最多 3 次图像生成（初次 1 + 重试 2）；每次请求一张；默认第一完整返回图。响应格式修复最多 2 次，不重新生成图片。
  • 默认图像最大 50 MiB、最大 40 MP；更大输入须显式创建另一个统一预处理配置，不能静默压缩。
  • 分辨率变化记录。默认宽高比相对误差 ≤ 0.02、全图构图保持；尺寸不等本身不直接判错。超过误差标记为几何不合规；不能自动裁切修复。
  • 默认无色彩回对齐、自动白平衡或锐化等后处理。原始输出始终保留。
  • 诊断 / 编写 / 验证各角色的会话明确分开；编辑器每轮用新会话或受支持的隔离调用，防止隐式连续编辑。

状态机、轮次与终止

状态及转移

12 个示意阶段合并为 8 个可持久状态；发任务、解析、检查为内部事件，不制造用户需要点击的空阶段。

operation_status 与阶段分离：active|paused|blocked|cancelled。paused / blocked 保持 workflow_status、round 与 pending_task_id。失败任务响应 status=error 进入 blocked，不自动生成新编辑任务。取消创建终止事务：FINISHED / cancelled，success=false。

判定顺序与矛盾响应

  1. 外层身份、Schema 与资产校验失败：拒收，当前阶段不变；写 quarantine 与事件。
  2. verdict=correct 同时 needs_redo=true：视为响应矛盾，要求同一 verifier 任务解释 / 修正 JSON；不消费编辑预算。
  3. verdict=correct 但有 fail checklist 或 moderate/severe defect：响应矛盾，同上。mild defect 可为可忽略残留，但必须 reasoning 解释且该 checklist 非 fail。
  4. 图片几何不合规时不允许成功。Verifier 可反馈后走 refine；预算耗尽时只能 incomplete。
  5. 合法 verification 到达后按上表做 finish 或 refine，不从 score 分数臆造一个隐藏 success 阈值。

无信息可恢复时 verifier 可以给 incorrect + needs_redo=false：这表示继续采样可能编造，不代表成功。报告使用 workflow_completed=true, restoration_success=false。

工具的例外

正常主组：只运行诊断选择的工具；不能根据 has_text=true 再由 controller 擅自增添 OCR。计划空时立即 compose。未知工具 ID 拒收诊断，不能静默忽略。

必需工具报错 / 缺失时 blocked。人工可提交 skip_tool 干预理由，之后以 deviated=true 单独跑探索 case；不可再算作完整工具主组。no_detection 必须是成功执行工具后的空检测结果，不能代替未运行。

轮次与预算

本地 round 从 1 开始；verifier 的 best_round 保留官方零基 attempt index：0 对应 round_001。request.context.attempts 明列 index、round、任务 ID 与图像哈希；禁止凭文件名猜对应关系。

发 execute 前在事务中 reserve 一个 generation 槽。用户实际提交编辑器时记 execution_submitted；收到图像 / 服务端明确已生成时记 consumed。超时并不知道模型是否运行时保持 reservation，等待用户确认，不自动释放或重发。明显未提交时可显式取消 reservation；所有变化写日志。重发相同任务响应不会增加 round；外部再次生成计额外生成，不能以“网络错误”抹掉采样成本。

reserved 是仍未确认完成 / 取消的槽数；确认本次生成后释放本次 reserved 槽，并按实际生成图片数增加 consumed。派发时检查 consumed + reserved < max_generations；外部意外多生成也如实计数，不能截断账本以伪装守预算。consumed 超过预算后不得再派发，并将 extra_sampling 偏离写入报告。默认一任务一图，正常 consumed 永不超过 3。

选定结果

默认遇到第一成功轮次即停止；FINISHED/accepted 交付该轮。若耗尽预算或不可继续，按最后一次 verifier 比较全部历史的 best_round 指定候选；排除文件损坏和几何不合规轮次。该索引越界或指向不合规输出则先要求格式修复，仍无法修复时选 earliest valid round 作 未通过候选。若无 valid 输出，final_output=null。

Verifier 最后一次 verdict / checklist 描述的是最新图，而 best_round 可能更早。final success 必须取被选中轮次自己的 verification 且 gates 通过；不得把最新轮的成功标在较早图上。所有失败输出保留。baseline 第一完整图不由 harness verifier 帮它选优。

此选图规则是适配版固定规则，与官方 selection.py 的分数与 NR fallback 不完全相同，必须记录差异。

持久化与重启

控制器只根据已落盘 request、commit 事务和有效 done 恢复。重启先取得写锁，校验事务连续性，重建 state / events，再扫描未消费 done。部分 .tmp / .part 永远不推进。任务修复使用相同 task_id 和新 response revision，不重跑模型图像编辑。

不允许被替换或取消的旧 pending task 响应改变新状态；任务身份与发出 revision 一起校验，当前 revision 可能因 telemetry 已更新，具体见文件协议。晚到输出留存、隔离，生成成本照实登记，但不替换当前 pending task。首次正式成功响应被接受后，任何同 task 的不同结果是冲突；不自动取“更好”一份。

文件交接协议 v1.0

单任务生命周期

  1. Controller 在 tasks/<task_id>/ 写不可变 request.json、prompt.txt，更新状态事务。
  2. 角色适配器读 request 和允许的资产，执行一次任务。
  3. 写 response.json.tmp；flush、fsync、关闭，用同目录 rename 替换为 response.json。
  4. 图片先写 .part，关闭后改为最终文件，计算 bytes SHA-256 与解码后的 RGB 像素哈希。
  5. 最后写 done.json.tmp，关闭并 rename 为 done.json。done 内包括 response bytes SHA-256 和所有输出资产哈希。
  6. Watcher 只消费 done；校验后由唯一 Controller 提交状态事务。

临时文件与目标在同一卷。Windows 报 sharing violation 时短退避重试（100/200/400/800/1600 ms），仍失败 blocked。不能在文件未关闭时写 done。

字段

request.schema.json：身份、角色、round、attempt_index、expected_state_revision、输入哈希、profile、模板哈希、prompt_file、payload_schema、allowed_assets、context、response 路径、done 标记路径。

response.schema.json：原样回传身份、role、round、revision、input_sha256；status 为 ok 或 error。ok 有对应 payload 且 error=null；error 有 error 对象且 payload=null。provenance 记录实际显示的模型 / 版本、会话与传输方式；未暴露后端版本写 null，不能猜成某个 GPT-Image API ID。

done.schema.json：task_id、response_file、response_sha256、artifact_hashes、committed_at。payload_schema 指向本包下的 schema；request 只允许在锁定配置中列出的 schema 文件。

数据统一 UTF-8；时间使用带时区的 ISO 8601（推荐 UTC Z）。哈希为小写 64 位 SHA-256，由本地文件桥 / controller 计算，模型不得填想象值。JSON 重复键、NaN、Infinity、字符串布尔值一律拒收。仅允许最外层一个完整 markdown JSON fence；不从自由散文中捞取“看起来像 JSON”的片段。

资产与访问范围

文件 path 为 case 内相对路径；拒绝绝对路径、盘符、..、反斜杠、符号链接 / junction 逃出根目录。resolve 后必须仍在 case 根。资产声明：path、sha256、kind、width、height；JSON / 文本的 width、height 为 null。图片以解码实测尺寸为准，不能信任 filename。

diagnose 只允许 canonical；compose / refine 允许原图、合法证据与失败反馈；execute 只允许 canonical（实际编辑消息仅送图片 + instruction，文件 envelope 不发送给编辑模型）；verify 允许原图与全部历史输出、固定 intent / checklist / 可用 measurements，不允许 composer / refine instruction。

幂等和冲突

幂等键是 (task_id, response_sha256)，不是 filename。相同键被处理两次，第二次返回 already_processed，不推进、不增加 round。相同 task 不同内容：首个被校验并接受的 response 为正式值；后续置 quarantine/conflict，不能覆盖正式文件。未通过格式校验的响应可修复为新 revision，但原 raw 全部留存。

文件发现顺序不代表生成顺序。每个 execute task 只有一个 canonical candidate；若编辑器返回多个图片，适配器记录 provider 顺序，采用第一完整图片，其余归档为 extras 并登记多输出，不让人挑图。若顺序无法确定，阻塞并记录为协议偏离。

状态事务与事件

state.json 是唯一当前状态快照；只有 Controller 可写。transactions/<revision>_<tx_id>.json 是持久恢复凭据，含 previous_revision、完整 next_state、event、accepted_response_sha256、next_task_id 与下一任务哈希。

提交步骤：持锁 → 校验当前 revision → 下一任务文件临时落盘并校验 → 事务文件原子提交（commit point）→ 更新 state 快照 → 追加 events.jsonl 并 flush。若任一步断电，重启按已提交 transaction 重放到 state，并按 event_id 去重重建 events.jsonl。未提交的任务目录不派发；跳过 / 不连续 revision 则 blocked。

events.jsonl 是可再生审计投影，不与 state 争夺写权限。记录 case_created、task_issued、execution_submitted、response_accepted、response_rejected、tool_registered、state_changed、manual_intervention、case_finished。event_id / tx_id 唯一，不使用本地时间戳作为唯一 ID。

降级导入

用户粘贴仅 payload 的 JSON 时，UI 从当前不可变 request 补 envelope；用户只需选择实际模型显示名。UI 保存 raw，再做相同 Schema 检查、文件哈希与 done 提交。writer=manual_import, transport_mode=clipboard_import。禁止 UI 在 JSON 解析失败时调用另一模型偷偷改写结果。

用户保存编辑图片后，通过“提交当前任务结果”选择该文件；UI 将 bytes 复制到当前 task 目录，登记 metadata 和完成标记。也可保存为 UI 明示的任务路径，由桥做同一登记动作。不能监控整个 Downloads 后自动把最新图片匹配到某个 case。

必须校验的语义规则

Schema 之外：哈希对应锁定 canonical；expected revision 等于任务发出时 revision；role 等于当前 pending role；round / attempt index 映射成立；工具清单只含锁定计划；bbox 的 x0<x1、y0<y1；best_round 对应已展示合法输出；stage payload 的 Schema 选取固定；provenance 时间顺序正确；done 所列文件完整且哈希一致。详情见验收矩阵。

expected_state_revision 与 request 中锁定的发出 revision 比较，不与 telemetry 更新后的最新 state.revision 直接比较。登记 execution_submitted 等事件可能更新 state revision，但只要该 request 仍是 pending_task_id，响应可接受；验收事务另外对最新 state revision 做 compare-and-swap。被替换 / 取消的旧 pending 任务响应一律隔离。这样既防旧响应，也不会因记账导致有效输出无法回写。

date-time 检查必须真实启用（jsonschema 的默认 FormatChecker 可能缺少可选依赖）；启动自检确认已注册，否则报错并安装 rfc3339-validator。还需校验真实时间顺序与时区，不能只做字符串格式检查。

固定角色会话

初次把 prompts/00_operator_system.txt 用作操作约定，并在界面选择模型显示名称。主控是本地程序，ChatGPT 不做隐藏状态控制。分别建立 Diagnoser、Composer/Refiner、Verifier 三个任务入口；编辑器用独立会话。每次完整任务自包含，不能依赖上一个 case 的记忆。

Diagnose

输入 canonical 图和固定 intent；模型只观察退化和敏感区域，按图像需要规划工具。返回 diagnosis.schema.json 数据。不执行图像编辑，不因“照片有一点暗”自动认定需把夜景变白天。

Compose

控制器按计划自动运行本地工具或命中缓存，收齐证据后派发。模型必须同时看到原图及工具地图 / 框 / OCR 文本；仅有 depth 文件路径不算已读深度。模型生成 composition.schema.json，其中 instruction 是实际用于编辑的文字。系统只渲染任务模板、校验与抽取，不用规则拼一段所谓“智能结果”。

Execute

新建图像编辑会话。只发送 canonical 原图与 instruction 原文；不能把 task envelope、证据图、历史输出或诊断 JSON 一起附给编辑器。请求一张图片。返回后不在同一结果上继续改，保存原始生成图到该 task 的 output 文件，再登记完整 metadata。

真实生成图片的功能可能与本地 Work 文件写入在不同会话 / 模式；工程师必须测通，不通过就使用上传 / 保存通道。仅导出可下载链接不能证明已经写到 C 盘。

Verify

独立验证入口读取原图与所有已登记输出；明确哪张是最新图。接收固定 intent 和 checklist，但不给编辑 Prompt / 模型名称 / 组名 / 自评。核查“退化处理”与“保真”分别是否满足。返回 fields 描述最新图，best_round 比较全部历史。

Refine

Composer/Refiner 读取原始图、已有证据、上轮 instruction、失败输出和反馈，产出新的 composition。重试输入重新回到原图。此前已通过区域保留到新指令，不为了局部修复扩大改图范围。

图像处理与几何

保留原始 bytes 与 metadata；canonical 的 EXIF 方向与已知 ICC 转 sRGB 操作写记录。不做自动曝光、降噪、白平衡、缩放或锐化。8bit 显示域是第一阶段默认；DNG/RAW/HEIC 先在独立统一步骤导出，原 bytes 留存，不能把导出当真实 RAW 恢复。

返回图分辨率与色彩信息真实记录；无 ICC 时按本实验默认 sRGB 解释，声明这个假设。将带 alpha 的生成图片用于评价前采用固定白底处理，并同时保存原图；默认要求生成 RGB 无透明。宽高比误差超 2% → 几何不合规；不静默拉伸 / 裁切。尺寸变化在适配版允许，官方 exact size gate 差异明确记入报告。

静态检查与质量检查分离

文件不可解码、损坏或未知类型属于传输失败，不推进 verifier。图像可解码但场景替换、重复原图或几何改变属于算法输出，必须记入结果，不能以“文件失败”重试掩盖。

input/output 的结构 SSIM、平均亮度、颜色漂移可以作为观察量；不使用与 LQ 的 PSNR / SSIM 排序恢复质量。场景很暗时自然提亮会降低与 LQ 相似度，不能据此否定恢复。文本核对只在原图或工具证据明确可读区域执行；退化图无法知道的字符不可把生成“更清晰”当正确。

研究问题与结论边界

问题：在同一 ChatGPT 图像编辑功能下，诊断 + 按需工具 + Prompt 编写 + 验证反馈能否比直接编辑获得更好的退化去除，同时保持内容？本地 UI 流程通过只证明交接可用。后端模型不可锁定时，结论是“所记录 ChatGPT UI 条件下的表现”，不能宣称严格复现论文 API 数值。

数据与评价

R0 一张真实拍摄图仅验证端到端与失败记录。后续 pilot 建议 12 张分层照片（低光 / 噪声、模糊、雨雾、文字、人脸、混合退化各有覆盖，可跨标签），验证工程与评测是否有分歧；若看算法趋势，预注册至少 30 张独立真实拍摄图，分层、全部纳入结果。这个样本数是实施建议，不是功效保证。开发图不能混进冻结测试集。

有可信对齐 GT：PSNR/SSIM/LPIPS/DISTS，统一几何与色彩预处理并记录；GT 不用于在线 Prompt / verifier / 选图。没 GT：原图对比盲评、可读文字一致性、人脸 / 结构漂移、退化残留、逐区域失败率。无参考 IQA 作为辅助，不能单独证明保真。

独立最终评测不能复用闭环 verifier 的 verdict 作主指标。人盲评推荐随机 A/B 左右、隐藏组名，分“去退化”“内容保真”“可用性”三项；记录平局与不可判断。以图为统计单位，重复生成属于同图内相关采样。报告 paired differences、胜/平/负、95% bootstrap CI 和灾难性改动比例；不同类别单列。

官方 DF 为逐图 sqrt(D*F) 后平均，D/F 为 0–100；本地 verifier 的 0–10 scores 不可改名为官方 DF。本包保留 DF Prompt 快照供工程师后续严格装配；使用新模型 / 修改 Prompt 的 DF 必须命名 adapted_DF。工程 R0 不要求装全量 IQA 工具。

Controller 环境只放流程、Schema、文件与 UI 依赖，不能 import Paddle / torch / InsightFace。使用配置好的 Python executable 启动独立工具进程，argv 为固定白名单列表，不执行模型输出的命令。

初始保护配置为工程预算而非运行保证：启动前 available RAM ≥2048 MiB；worker RSS 上限 3072 MiB；运行中 available RAM <512 MiB 则中止 worker 并保留日志；每 200 ms 采样 worker 及子进程 RSS（是采样峰值，不能声称精确峰值）。没有内存余量时 resource_wait，UI 提示关闭占用程序或导出 GPU 作业，不反复重启。

初始 timeout：T2 120 秒、T1 600 秒、T3 600 秒、T4 900 秒，含模型加载；探测后按测得耗时另冻结配置。timeout / oom / import_error / model_missing 分开记录。同配置瞬时 I/O 可重试一次；OOM 不自动降分辨率或换模型。降低尺寸必须形成新 profile / 参数哈希。

GPU 批量阶段可一工具进程串行处理多图以摊薄加载，但仍禁止不同框架同时抢同一 GPU；GPU 总队列默认单 worker。未来并发需要单独资源测试，不是 280 张的前置条件。

4. 环境和离线准备

Windows 建议 3 个环境：venv_controller、venv_t12_cpu（Paddle+ORT）、venv_t34_cpu（torch+YOLOE）。若 T1/T2 依赖冲突再分开，不把所有依赖倒入 Controller。Linux 用独立 t12_gpu / t34_gpu；SAM 3 相关环境按官方兼容要求和实际锁定版本搭建。部署准备与恢复运行分开。

model_registry.example.json 中的未安装路径 / SHA 为 null、ready=false；工程师完成下载、组件清单哈希、SDK 导入、设备后端和一张 warm-up 后才生成本机可用 registry。记录 Python / SDK / torch / Paddle / ORT / CUDA / driver 的版本与源码 commit。不能把“包 import 成功”当作模型推理通过。

运行默认 offline=true，auto_download=false，auto_install=false。YOLOE 文本路径要预备文本编码器 / tokenizer / 词表，首次 set_classes 的安装下载工作放在部署阶段；固定类别时可预生成 prompt embedding 或静态导出，导出后类别不可动态变更，要另记产物哈希。SAM 3 checkpoint 访问由用户 / 工程师在准备阶段完成，运行不修复认证、不输出凭据。

6. 图像与变换

input_sha256 始终指 Executor 使用的 canonical bytes，而不是 worker 临时 resize 图。raw source bytes SHA 另存；工具与模型原始结果都不得回写 / 提亮 canonical。缓存复用依赖 canonical SHA 和 preprocessing version，不能只靠 manifest 的同名 filename。

工具可使用独立缩放视图：cpu_probe 的 T3/T4 默认 full-frame source-view long edge≤1280，推理尺寸 DA 518 / YOLOE 640；T1 原图执行但 det max-side 初始960；T2 full-frame640。GPU full profile 的 source-view / SDK 参数另冻结，不能沿用低分辨率数据却仅将 model_name 改成 Base。

Depth Anything 作者 infer_image 接收 OpenCV BGR 并在内部转 RGB；若从 canonical PIL RGB 获取数组，要在该 API 边界转为 BGR 一次。不能因方案写“RGB”而在 SDK 前后重复交换通道；其他 SDK 按它们各自约定处理，Composer 看到的原图保持 RGB。

所有 OCR polygons、bbox、kps 最终为 canonical_norm。full-frame、crop、resize、letterbox 每个视图独立记录 view_to_canonical 3×3 矩阵；图像网格 shape 与 view ID 明列。Tiled OCR 不能用单个全局变换代替多个 tile。深度连续值双线性缩放，离散 labels 最近邻；native masks 使用锁定的插值 / 阈值规则；保留原始输出。不把上采样当新增细节。

7. 小文字和小人脸的两条路径

默认 full_frame_v1 不加任意人工 crop。人像/长焦 pilot 的质量审查记录漏检 / 错识别和 source pixels；high-confidence 也不能等同正确。

若全图缩放会吞掉小字 / 脸，另建 hardcase_roi_v1：固定网格切块（含重叠）或冻结的诊断 ROI → 局部执行 → 坐标反映射 → 固定去重。原图不可读细节依然不可验证。人工手选 ROI 必须标 manual_variant。ROI 政策、tile size / overlap / merge thresholds 纳入缓存键与实验配置，结果与 full_frame 分开报告。

8. 缓存与 case 快照

路径：Data/annotations/cache///，一个完成目录含 evidence.json、raw、map/overlay 和 ready.json。cache_contract.schema.json 规定 key 内容：canonical SHA、canonicalizer version、tool_id、tool implementation/revision、model bundle SHA、精确推理参数、precision/device/backend versions、prompt-set SHA、adapter version、ROI policy。序列化固定为 JSON(sort_keys=True,separators=(',',':'),ensure_ascii=False,allow_nan=False) 的 UTF-8 bytes；SHA-256 后得 cache_key。prompt 顺序有语义，不排序类别列表。

只有内容与文件哈希均通过的 ok cache 可用；failure 只保留运行日志，不能当 empty 检测缓存。相同 cache_key 由一个进程计算，另一个等待，不重复运行。完成写临时目录→rename→ready 最后写入；断点续跑检查真实资产，不仅检查 evidence.json 存在。

绑定 case 时将所需资产复制到 case 的 immutable tools 目录（第一阶段默认复制，避免同步 / 用户修改污染），所有相对路径重写；保存 binding、cache key 和 evidence snapshot SHA。只给 Composer 计划内工具。升级模型会得到新 key 和新 case / 显式分支，不覆盖旧已完成 case 的证据与 instruction。只工具变动的假设也必须重跑 Compose→Execute→Verify。

9. 失败政策

延续 v1.0 formal 的 all_planned_tools_required：任一计划工具失败则 blocked / resource_wait，未到 Composer。CPU probe 可配置 continue_with_unavailable：明确错误原因、缺失工具与 partial_evidence，自动继续只为工程探索，deviated=true，不算完整证据主组。策略建 case 时冻结，不因为跑得慢临时换规则。

锁定官方 tools.py 本身允许 soft unavailable；因此 require-all 是我们更严的验收设计，不应声称它是官方必需规则。未检测到对象=工具运行 ok / empty；模型运行失败=unavailable，两者不同。缺图、OOM、坏 Mask、unknown label 分开记录。

工具不会修复原图。辅助工具失败不自动调用图像编辑模型来伪造证据。若 Composer 要额外工具，由诊断修订任务形成新已记录计划，不能绕过计划从缓存里自由挑图。

10. GPU 迁移与 280 张作业

Controller 不直连远程服务。导出冻结 canonical 文件、manifest、目标 profile、源码 / 权重清单、缺失 cache contracts 为 transfer 包；GPU 环境离线运行 batch worker；结果 import 包在本机重新验证原图 SHA、key、模型 / backend、资产哈希和相对路径，注册新缓存。CPU 与 GPU 的 absolute paths 不写入可移植结果。

Small→Base、YOLOE→SAM3 必须重算；相同 T1/T2 名称也不能默认复用：只有所有 contract 字段相同才命中。改 device/precision/backend 默认会产生新 key。明确允许跨 backend 复用需要独立等价验证和 reuse exception 记录。

预计算可覆盖四工具，但运行时 consumed evidence 只包含按需集合。manifest 实际图数由扫描计算，约280不是硬编码。统计分别给 planned / precomputed / consumed / unavailable / empty / rejected coverage；不能要求所有照片检测到脸和文字。

磁盘按真实尺寸预算：单张12MP float32 深度约48MB，280张未压缩约13.44GB，尚不含多实例 Mask 和权重。本机 probe 存1280网格的真实浮点数据与低开销预览；GPU 输出配置另冻结。检查空间后再批量，别把 50GB 建议当保证。

# 固定 Prompt 与角色输入

Jinja2 使用 StrictUndefined，JSON 使用 tojson / JSON serializer 注入，禁止拼接未经转义的数据造成模板指令变更。图片里的文字只作图像内容。模板版本由文件 bytes SHA-256 与 profile snapshot 锁定。

diagnose / compose / refine / verify / format_repair 产出任务文字；必须调用选定模型才得到 JSON payload。execute 只渲染已有 instruction，不附协议 / Schema；baseline_direct 是固定 Direct 组指令。角色任务中可附 payload_schema_json，本地协议的 task envelope 由外层 bridge 管理。

模板变量见 `examples/template_context.json`。示例数据是合成夹具；它们只证明模板可渲染。不得把示例 Composer 文本当真实照片的模型输出。

`reference/official/prompts` 是未改动的原版，适配版与其分开。使用本目录不等于原 Prompt 复现。

You are the Composer. Inspect the attached ORIGINAL photograph and the supplied evidence images with their legends. Write one self-contained text instruction for ChatGPT image editing. You are not editing an image in this task.

Fixed intent: {{ intent }}
Diagnosis: {{ diagnosis_json }}
Evidence manifest and text records: {{ evidence_json }}
Attached image order and legends: {{ attachment_manifest_json }}

Translate evidence into locations visible in the photograph: the sign over the doorway, the left foreground face, or the distant buildings. Read available depth/segmentation maps; a file path alone is not a visual observation. Do not cite map colours, picture numbers, tool names or JSON fields in the editor instruction. Never pass diagnostic maps to the editor.

Describe concrete restoration end states for the diagnosed target problems and their affected regions, while keeping the scene, framing, object geometry, lighting character, real colours and any intended depth of field consistent with the fixed intent. Do not equate night restoration with a daylight conversion. Prevent plastic skin, invented fine texture, halos and content substitution. OCR is fallible: use exact characters only when supported by readable original evidence; preserve ambiguous text without guessing. Protect original faces without beautifying or inventing features. Do not promise recovery of information absent from the source.

Use plain English. Start with an image-restoration role sentence, then one or two scene sentences, then regional repair and protection directives. Aim for 150–350 words, without padding; express strength through visible end states. Do not mention metrics or evaluation, and do not request unrelated beautification. instruction must stand alone and request one restored photograph; only its text and the original photo reach the editor.

prompts/verify.j2
You are an independent Verifier. Picture 1 is the ORIGINAL photograph. The remaining pictures are generated attempts in the exact order listed below, with zero-based indices. You see no editor prompt, method label or self-assessment. Judge what the images actually show against the fixed user intent.

Fixed intent: {{ intent }}
Attempt identities / attachment order: {{ attachment_manifest_json }}
Known task types: {{ task_types_json }}
Optional measured observations (not proof of fidelity): {{ measurements_json }}

Apply this fixed adapted checklist; all seven keys are mandatory:
C1: The requested degradation is sufficiently removed in every affected region.
C2: Scene objects, geometry, fine detail and texture remain supported by the original; no invented content.
C3: Originally readable text preserves its characters, placement and shape; unclear text is not confidently invented. Use na only if there is no text.
C4: Faces preserve identity, features and natural skin; no beautification or fabricated anatomy. Use na only if there is no face.
C5: Composition and viewpoint remain the same; no crop, scene replacement or distorted shapes. A resolution change by itself is not a content change.
C6: Changes stay within the task; natural scene lighting, night mood, weather and intended depth of field are preserved unless the fixed intent requests otherwise.
C7: No material halos, plastic texture, ringing, oversharpening or new restoration artifacts.

Trace apparent recovered text/texture/structure back to ORIGINAL evidence, not just to plausibility. Unreadable source information cannot prove the generated content is true. Distinguish visible residual degradation from missing source information. Localized meaningful failure is a failure even if most of the frame looks good. Similarity to a degraded original alone is not a restoration-quality criterion.

Your checklist, defects, scores, overall, verdict and failure_mode describe the NEWEST attempt only. Scores are 0–10 and are diagnostic, not official DF scores. best_round is the zero-based index of the attempt you would deliver, ranked by fidelity first and sufficient restoration second; the first attempt may be best.

verdict=correct only when the task is adequately achieved without material content changes. needs_redo=true when a meaningful fixable defect remains. If the source lacks the information or successive attempts demonstrably cannot address the same defect, needs_redo may be false while verdict remains incorrect; explain why. Do not equate no redo with successful restoration. Do not emit correct with needs_redo=true or checklist fail. Use normalized ORIGINAL image coordinates for defects.

Return only JSON: reasoning, checklist, defects[{location,bbox_norm,issue,item,severity}], scores{restoration_sufficiency,fidelity,scope_discipline,naturalness}, overall, failure_mode, verdict, needs_redo, redo_priority, best_round, best_round_why.

# JSON Schema 使用说明

采用 Draft 2020-12。所有 `$id` 与 `$ref` 是本地注册的逻辑名称，不需要访问 harnessir.example。Schema Validator 必须显式注册本目录中的所有 Schema 并使用 FormatChecker，不能在线下载未知 Schema。

严格类型：不做 true/false 字符串或 int 的隐式转型。结构验证后继续执行 `docs/03_File_Protocol.md` 的语义校验。Schema 无法验证文件哈希、模型是否看过图片、best_round 是否指向当前案例或工具地图是否合法。

diagnosis / composition 保留官方核心字段名；verification 使用固定 C1–C7 的适配版 checklist。response.payload 根据 role 自动绑定相应 Schema；refine 复用 composition Schema。

`examples/` 是合成协议夹具，图片与哈希不是用户真实实验数据，不能直接送入生产 Controller。
